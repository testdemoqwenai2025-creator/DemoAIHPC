EditJumps — Antibody Lead Optimization

The first open-source implementation of Edit Flows and EvoFlows — edit-type generative models for antibody lead optimization. Trained on 1.66M antibody homolog pairs from the Observed Antibody Space (OAS) database. Instead of generating sequences token-by-token (like language models), EditJumps learns discrete edit operations (substitutions, insertions, deletions) that transform a suboptimal antibody into a better one — mimicking the natural evolutionary process. 📐 Mathematical formulation

Stage 1 — Antibody representation: x = (CDRH3, CDRL3) — the complementarity-determining regions
Antibodies are represented by their CDRH3 and CDRL3 sequences — the variable loops that bind antigens. The OAS database contains 1.66M paired homologs: (x_source, x_target) where x_target has better binding properties.
Stage 2 — Edit operation space: E = {sub(i, a→b), ins(i, a), del(i)} where i = position, a = source amino acid, b = target amino acid
Instead of continuous generation, EditJumps operates in discrete edit space. Each edit is a (position, operation, amino acid) triple. The model learns which edits improve binding — like natural evolution but computationally guided.
Stage 3 — Edit Flow: p(e₁, e₂, ..., eₖ | x) = Πᵢ p(eᵢ | x, e₁...eᵢ₋₁) Autoregressive model over edit sequences, not token sequences
Edit Flows model the probability of a SEQUENCE of edits given the starting antibody. This is fundamentally different from sequence models (which generate tokens) — Edit Flows generate TRANSFORMATIONS. The autoregressive factorisation captures dependencies between edits (e.g., edit at position 10 depends on what was edited at position 5).
Stage 4 — EvoFlows: p(x* | x) = Σ_edit_sequences p(e_seq | x) · 𝟙[apply(e_seq, x) = x*] Evolutionary search over edit sequences
EvoFlows extends Edit Flows with evolutionary search: sample many edit sequences, apply them to x, evaluate the results, and keep the best. This mimics natural selection — mutations (edits) are generated stochastically, and selection (binding score) determines survival.
Stage 5 — EditJumps: p(x* | x) = Σ_jumps δ[apply(jump, x) = x*] Discrete jumps instead of sequential edits — faster + more interpretable
EditJumps simplifies Edit Flows by replacing the autoregressive sequence with discrete "jumps" — each jump is a set of simultaneous edits applied in one step. This is faster (no autoregressive generation) and more interpretable (each jump is a single decision). The key innovation: training on 1.66M OAS homolog pairs teaches the model which jumps occur in nature.

💻 Runnable code

# EditJumps — simplified implementation
import numpy as np

class EditJumps:
    def __init__(self, vocab=20):  # 20 amino acids
        self.aa = "ACDEFGHIKLMNPQRSTVWY"
        # Learned edit probabilities (simplified — real model uses Transformer)
        self.edit_probs = np.random.rand(50, 3, 20)  # (pos, op, aa) = (50, 3, 20)
        self.edit_probs = np.exp(self.edit_probs) / np.exp(self.edit_probs).sum(axis=2, keepdims=True)

    def sample_jump(self, seq_len=30):
        # Sample a set of simultaneous edits (a "jump")
        n_edits = np.random.randint(1, 5)
        edits = []
        for _ in range(n_edits):
            pos = np.random.randint(0, seq_len)
            op = np.random.choice([0, 1, 2], p=[0.6, 0.2, 0.2])  # sub/ins/del
            aa = np.random.choice(20)
            edits.append((pos, op, aa))
        return edits

    def apply_jump(self, seq, edits):
        # Apply a set of edits to a sequence
        result = list(seq)
        for pos, op, aa_idx in edits:
            if op == 0:  # substitution
                if pos < len(result): result[pos] = self.aa[aa_idx]
            elif op == 1:  # insertion
                result.insert(pos, self.aa[aa_idx])
            else:  # deletion
                if pos < len(result): result.pop(pos)
        return ''.join(result)

    def optimize(self, seq, n_jumps=100):
        # Evolutionary search: sample jumps, keep the best
        best = seq
        best_score = 0
        for _ in range(n_jumps):
            edits = self.sample_jump(len(seq))
            candidate = self.apply_jump(seq, edits)
            score = np.random.rand()  # simulated binding score
            if score > best_score:
                best, best_score = candidate, score
        return best, best_score

# === Example: optimize a CDRH3 sequence ===
np.random.seed(0)
model = EditJumps()
parent = "ARSDYSGYFY"  # starting CDRH3
optimized, score = model.optimize(parent, n_jumps=50)
print(f"Parent:  {parent}")
print(f"Optimized: {optimized} (score={score:.3f})")
print(f"Edits: {len(optimized) - len(parent)} positions changed")

🧠 Deep thoughts

When to use edit-type models vs autoregressive generation

USE WHENYou have a starting antibody with known properties (parent) and want to improve it (lead optimization). When the search space of possible improvements is discrete (amino acid substitutions). When you have paired homolog data (source → target) from natural evolution. When interpretability matters (each edit is human-readable).
AVOID WHENYou're designing antibodies from scratch (no parent — use autoregressive models like ESM-IF or IgLM). When you need continuous gradient-based optimization (use differentiable sequence models). When the edit space is too large and sampling is inefficient.
WHYEditJumps mirrors natural evolution: antibodies improve through somatic hypermutation (random edits) + selection (binding). Edit Flows learn the distribution of edits that occur in nature from 1.66M OAS pairs. This is more biologically grounded than autoregressive generation (which doesn't model the "improvement" process). The "jump" simplification makes it practical: each jump is a single decision instead of a sequence of autoregressive steps.

🔬 Comparison

EditJumps vs other approaches

vs Autoregressive models (ESM-IF, IgLM)Autoregressive models generate sequences token-by-token — good for de novo design but not for optimization (no notion of "improvement"). EditJumps generates EDITS — explicitly models the improvement process. Better for lead optimization; worse for from-scratch design.
vs Edit Flows / EvoFlows (original papers)Edit Flows use autoregressive edit sequences (slower, but model edit-edit dependencies). EditJumps simplifies to discrete jumps (faster, more interpretable, but loses some dependency modelling). EditJumps is the first OPEN-SOURCE implementation — the original papers didn't release code.
vs Directed evolution (wet-lab)Directed evolution randomly mutates + screens — 10⁶ variants tested, 6 months. EditJumps computationally samples edits — 10² jumps, minutes. 10,000× fewer experiments needed. But EditJumps predictions need wet-lab validation.
vs Claude toxin binder designClaude designs binders from scratch (de novo). EditJumps optimises existing antibodies (lead optimization). Complementary: Claude discovers candidates → EditJumps optimises them. Together: full antibody drug discovery pipeline.

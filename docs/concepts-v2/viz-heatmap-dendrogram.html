Heatmap + Dendrogram

A heatmap + dendrogram is the canonical visualisation for hierarchical clustering. The dendrogram (tree) on the left/top encodes the merge order: bottom-up, the closest pairs of rows (or columns) merge first, and the tree height is proportional to the distance at the merge. The heatmap's rows + columns are reordered to match the tree — so adjacent rows in the heatmap are similar, and the cluster boundaries are visible as visual blocks. Inspired by GenomeSpy v1.2.0's new dendrogram support (LinkedIn post by Oskari Lehtonen). 📐 Mathematical formulation

Stage 1 — Pairwise distances:
d(i, j) = ‖x_i − x_j‖₂ (Euclidean) or 1 − corr(x_i, x_j) (Pearson)
Start with N data points (rows of the data matrix X). Compute all pairwise distances. Euclidean distance is the default; 1−correlation is preferred for gene expression (it's scale-invariant — captures pattern similarity, not magnitude). The choice of metric is the most important parameter — it determines what "similar" means.
Stage 2 — Agglomerative linkage (how clusters merge):
Single: d(A,B) = min d(a,b) (nearest neighbour)
Complete: d(A,B) = max d(a,b) (furthest neighbour)
Average: d(A,B) = (1/|A||B|) Σ d(a,b) (UPGMA)
Ward: d(A,B) = √[ (|A||B| / (|A|+|B|)) · ‖μ_A − μ_B‖² ] (minimises variance)
At each step, find the closest pair of clusters and merge them. The linkage criterion defines "closest pair". Average linkage (UPGMA) is the safe default — robust to outliers and well-balanced. Ward's linkage minimises within-cluster variance — produces compact spherical clusters. Single linkage creates "chaining" artefacts (long thin clusters). Complete linkage is the opposite — produces tight compact clusters but sensitive to outliers.
Stage 3 — Dendrogram height = merge distance:
height(merge_k) = d(A_k, B_k) at the k-th merge
The y-axis of the dendrogram encodes the distance at which each merge happened. Tall vertical bars in the dendrogram indicate that two clusters merged at a large distance — they're dissimilar, suggesting a natural cluster boundary. Short bars indicate close merges — within-cluster. To choose the number of clusters, "cut" the dendrogram at a height where the bars are tall.
Stage 4 — Heatmap cell colouring:
H[i,j] = (x_ij − μ_j) / σ_j (z-score normalisation per column)
colour = red if H > 0, blue if H < 0, white if H ≈ 0
Before colouring, each column (feature) is z-scored to mean 0, std 1. This is essential — without it, a feature with magnitude 1000 would dominate the colour scale and obscure the pattern. Red-blue diverging palette (not red-green — colour-blind safe). White = average, red = high, blue = low. Some tools (e.g., Clustergrammer) use yellow-cyan; viridis is fine for sequential but not for diverging.
Stage 5 — Reorder rows + columns to match dendrogram leaves:
order = leaves_of_dendrogram_in_left_to_right_traversal
After clustering, the rows of the heatmap are reordered so that adjacent rows are similar (per the row dendrogram), and columns are reordered similarly (per the column dendrogram). This produces the characteristic "block diagonal" pattern of clustered heatmaps — clusters appear as visually-coherent blocks. 💻 Runnable code

scipy.cluster.hierarchical + seaborn

# Hierarchical clustering + heatmap + dendrogram
# Math→Code mapping:
#   X → data matrix (n_samples × n_features)
#   d(i,j) → pairwise distances (pdist)
#   d(A,B) → linkage (linkage function)
#   height → dendrogram y-axis
#   H[i,j] = (x_ij - μ_j) / σ_j → z-score normalisation
import numpy as np
from scipy.spatial.distance import pdist, squareform
from scipy.cluster.hierarchy import linkage, dendrogram, fcluster
from scipy.stats import zscore
import matplotlib.pyplot as plt
import seaborn as sns

def hierarchical_cluster_heatmap(X, row_labels, col_labels,
                                  metric='euclidean', method='average',
                                  n_clusters=3, cmap='RdBu_r'):
    # Stage 1: pairwise distances
    row_dist = pdist(X, metric=metric)
    col_dist = pdist(X.T, metric=metric)

    # Stage 2: agglomerative linkage (average = UPGMA)
    row_link = linkage(row_dist, method=method)
    col_link = linkage(col_dist, method=method)

    # Stage 3: extract cluster assignments by cutting dendrogram
    row_clusters = fcluster(row_link, n_clusters, criterion='maxclust')

    # Stage 4: z-score normalisation per column (feature)
    X_z = zscore(X, axis=0)  # (x_ij - μ_j) / σ_j

    # Stage 5: clustered heatmap with dendrograms
    g = sns.clustermap(
        X_z, row_linkage=row_link, col_linkage=col_link,
        row_colors=[plt.cm.tab10(c/10) for c in row_clusters],
        cmap=cmap, center=0, figsize=(10, 8),
        xticklabels=col_labels, yticklabels=row_labels,
        dendrogram_ratio=(0.15, 0.15),
        cbar_kws={'label': 'z-score'}
    )
    g.ax_heatmap.set_xlabel('Features')
    g.ax_heatmap.set_ylabel('Samples')
    return row_link, col_link, row_clusters

# === Demo: cluster 20 synthetic samples × 8 gene-expression features ===
np.random.seed(42)
n_samples, n_features = 20, 8
# 3 underlying clusters with different expression patterns
cluster_a = np.random.randn(7, n_features) + [2, 1, -1, 0, 1, -2, 0, 1]
cluster_b = np.random.randn(8, n_features) + [-1, -2, 1, 2, -1, 1, 0, -1]
cluster_c = np.random.randn(5, n_features) + [0, 0, 0, 0, 0, 0, 2, -2]
X = np.vstack([cluster_a, cluster_b, cluster_c])
samples = [f'S{i+1}' for i in range(n_samples)]
genes = [f'G{i+1}' for i in range(n_features)]

row_link, col_link, clusters = hierarchical_cluster_heatmap(
    X, samples, genes, metric='euclidean', method='average', n_clusters=3
)
print(f"Cluster assignments: {clusters}")
print(f"Row dendrogram has {len(row_link)} merges")
print(f"Max merge height: {row_link[:, 2].max():.3f}")
print(f"Min merge height: {row_link[:, 2].min():.3f}")
plt.title('Hierarchical Clustering — 20 samples × 8 features')
plt.show()

🧠 Deep thoughts — when to use dendrograms vs t-SNE/UMAP

Strategic guidance for choosing a clustering visualisation

USE WHENYou want to reveal hierarchical structure (e.g., subtypes within subtypes). Gene expression datasets often have a tree-like structure: cancers → subtypes → sub-subtypes. Dendrograms make this hierarchy explicit — you can cut at multiple heights to get different granularities.
USE WHENYou need to trace individual samples through the clustering. Each leaf of the dendrogram is a labelled sample (e.g., "TCGA-AX-A1C8"). t-SNE/UMAP scatter plots lose individual identity in the cloud; dendrograms keep it.
USE WHENYou want a deterministic, reproducible visualisation. Hierarchical clustering has no random seed — same input always produces same output. t-SNE/UMAP have stochastic initialisation; different runs give different layouts.
AVOID WHENYour dataset is large (>10k samples). The dendrogram becomes unreadable — too many leaves. Switch to t-SNE/UMAP for the global view, then use dendrograms only for the small clusters t-SNE reveals.
AVOID WHENYour data has no real hierarchy. If clusters are roughly spherical and equal-sized, k-means + scatter plot is more honest than a dendrogram that implies a hierarchy that doesn't exist.
WHYThe key insight is that the dendrogram's y-axis is a distance scale. This is information that t-SNE/UMAP simply cannot show. A "tall" vertical bar in the dendrogram is a quantitative statement: "these two clusters differ by this much". t-SNE only shows topology — "these points are near, those are far" — but the relative distances are distorted (the famous "t-SNE lies about distances" pitfall).
WHYDendrograms make cluster boundaries auditable. Cut the tree at height h → you get k clusters, and you can defend each cluster boundary with a distance value. With k-means, the cluster boundary is just "closest centroid" — no notion of how far apart the clusters are. For clinical applications where the cluster assignment determines treatment, this auditability is essential.

🔬 Comparison with related approaches

Dendrogram vs other clustering visualisations

vs t-SNE (Maaten 2008)t-SNE reduces to 2D for visualisation. It captures local structure well (near points stay near) but distorts global distances. Dendrograms preserve global distances (the y-axis is real distance) but are limited to hierarchical structure. Use t-SNE for "what does the data look like in 2D?" and dendrograms for "how do clusters relate to each other?"
vs UMAP (McInnes 2018)UMAP is faster than t-SNE and arguably preserves more global structure. But like t-SNE, the distance axis is arbitrary. Dendrograms give a quantitative distance scale that UMAP cannot. Trade-off: UMAP scales to millions of points; dendrograms cap at thousands.
vs k-means (MacQueen 1967)k-means produces flat cluster assignments (no hierarchy). You must choose k upfront. Hierarchical clustering lets you cut the tree at any height post-hoc to get any number of clusters — better for exploratory analysis where the "right" k is unknown.
vs DBSCAN (Ester 1996)DBSCAN finds arbitrary-shape clusters and handles noise. But it doesn't produce a hierarchy. Use DBSCAN when clusters are non-spherical; use dendrograms when you want to see the cluster-nesting structure.
vs Clustergrammer (Fernandez 2017)Clustergrammer is a web tool that produces the same heatmap+dendrogram visualisation as this card. GenomeSpy v1.2.0 added dendrogram support to enable exactly this kind of interactive exploration. The animation in this card is a static re-implementation of what Clustergrammer/GenomeSpy do interactively — focusing on the animation of the merge process as a teaching tool.

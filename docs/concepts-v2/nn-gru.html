Gated Recurrent Unit (GRU)

Simpler than LSTM (2 gates vs 3, no separate cell state). Often matches LSTM quality with fewer parameters.

h_t = (1 − z_t) ⊙ h_{t-1} + z_t ⊙ h̃_t
# GRU cell at time t:
# z_t = σ(W_z · [h_{t-1}, x_t])       (update gate)
# r_t = σ(W_r · [h_{t-1}, x_t])       (reset gate)
# h̃_t = tanh(W · [r_t ⊙ h_{t-1}, x_t]) (candidate)
# h_t = (1 - z_t) ⊙ h_{t-1} + z_t ⊙ h̃_t (hidden update — additive like LSTM)
import numpy as np

class GRUCell:
    def __init__(self, input_dim, hidden_dim):
        s = 1.0 / np.sqrt(hidden_dim)
        # 3 gates: update (z), reset (r), candidate (h~)
        self.W = np.random.randn(3 * hidden_dim, input_dim + hidden_dim) * s
        self.b = np.zeros(3 * hidden_dim)
        self.hidden_dim = hidden_dim

    def step(self, x, h_prev):
        xh = np.concatenate([x, h_prev])
        gates = np.split(self.W @ xh + self.b, 3)
        z = 1.0 / (1 + np.exp(-gates[0]))  # update gate
        r = 1.0 / (1 + np.exp(-gates[1]))  # reset gate
        h_hat = np.tanh(gates[2])           # candidate (simplified)
        h = (1 - z) * h_prev + z * h_hat    # additive update
        return h

# Example
np.random.seed(0)
gru = GRUCell(input_dim=3, hidden_dim=4)
x = np.array([0.5, -0.3, 0.8])
h_prev = np.zeros(4)
print(gru.step(x, h_prev))

🧠 Deep thoughts — when (and when not) to reach for this architecture

USE WHEN:you want LSTM-quality results with fewer parameters (3M-param LSTM ↔ 2M-param GRU often performs identically), smaller datasets where the extra LSTM gates would overfit, real-time / mobile / edge deployment where every parameter counts, baseline sequence models for new tasks before trying Transformers.
AVOID WHEN:you need every last percent of accuracy and have unlimited compute (LSTM slightly better on very long sequences), you're doing large-scale pretraining (Transformer dominates at scale), the task requires explicit cell-state inspection (LSTM's c_t is more interpretable than GRU's h_t).
WHY:GRU's insight is that LSTM's separate cell state c_t and hidden state h_t are redundant — you can collapse them into a single state. Fewer parameters means faster training and less overfitting on small datasets. Empirically, GRU matches LSTM on most NLP tasks within 1% accuracy. Use GRU as your default gated RNN; only reach for LSTM if you've tried GRU and it's not good enough.

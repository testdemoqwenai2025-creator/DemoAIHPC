📐 The math behind each stage

Stage 1 — Image as tensor: x ∈ ℝ^(H × W × C)
A 28×28 grayscale image = tensor of shape (28, 28, 1). A color image = (28, 28, 3) for RGB. Each value is a pixel intensity 0-255 (normalized to 0-1). The computer doesn't "see" an image — it sees a 3D array of numbers.
Stage 2 — FC layer parameters: 784 × 128 + 128 = 100,480 weights CNN layer parameters: (3 × 3 × 1 × 8) + 8 = 80 weights (1,256× fewer!)
A fully-connected (FC) layer connecting 784 inputs (28×28) to 128 neurons needs 784×128 + 128 = 100,480 weights. A CNN layer with 8 filters of size 3×3 needs only 3×3×1×8 + 8 = 80 weights. This is because CNN shares weights across all spatial positions — the same filter slides across the entire image.
Stage 3 — Convolution: y[i,j] = σ( Σ_{k=0}^{K-1} Σ_{l=0}^{L-1} W[k,l] · x[i+k, j+l] + b )
The filter W (size K×L) slides across the image. At each position, it computes the element-wise multiplication + sum (dot product). The result is a single number in the output feature map. σ is the activation function (usually ReLU). Two key inductive biases: locality (each output only depends on a small neighborhood) and translation invariance (the same filter detects the same feature everywhere).
Stage 4 — Multiple filters: F₁ detects edges, F₂ detects textures, F₃ detects shapes... Output: stack of feature maps → x' ∈ ℝ^(H' × W' × N_filters)
Each filter learns a different feature. Edge detectors (Sobel), texture detectors, shape detectors — all from the same input image. Deep CNNs stack layers: early layers detect simple edges, later layers detect complex objects. This hierarchical feature learning is why CNNs work so well for images.

💻 Runnable code — 2D convolution in numpy

# 2D convolution — the core operation of CNNs
import numpy as np

def conv2d(image, kernel, stride=1, pad=0):
    # image: (H, W) input — e.g., a 28x28 grayscale image
    # kernel: (K, L) filter — e.g., a 3x3 edge detector
    # stride: how many pixels to skip each step
    # pad: zeros added around the border
    H, W = image.shape
    K, L = kernel.shape
    # Pad the image
    if pad > 0:
        image = np.pad(image, pad)
    # Output dimensions
    out_h = (H + 2 * pad - K) // stride + 1
    out_w = (W + 2 * pad - L) // stride + 1
    out = np.zeros((out_h, out_w))
    for i in range(out_h):
        for j in range(out_w):
            # Extract the receptive field
            receptive = image[i*stride:i*stride+K, j*stride:j*stride+L]
            # Dot product + bias + ReLU
            out[i, j] = np.maximum(0, np.sum(receptive * kernel))
    return out

# Example: detect edges in a 8x8 image
np.random.seed(0)
image = np.random.rand(8, 8)
sobel_x = np.array([[-1, 0, 1], [-2, 0, 2], [-1, 0, 1]])
feature_map = conv2d(image, sobel_x)
print(f"Input: {image.shape} → Output: {feature_map.shape}")
print(f"Feature map (edges detected):\n{feature_map.round(2)}")

🧠 Deep thoughts — when to use CNNs vs MLPs

CNN vs MLP — the right tool for the right job

USE CNNWhen your data has spatial structure (images, spectrograms, seismic grids). When nearby pixels are correlated (locality). When the same feature can appear anywhere in the image (translation invariance). When you have limited training data (weight sharing = fewer parameters = less overfitting).
USE MLPWhen your data is tabular (each feature is independent — no spatial structure). When you need a simple classification head on top of CNN/Transformer features. When the input is small and fixed-size. MLPs are universal approximators but waste parameters on images.
WHYCNNs encode two inductive biases that match the structure of images: (1) Locality — a pixel's neighbors matter more than distant pixels, so a 3×3 filter captures useful patterns. (2) Translation invariance — a cat is a cat regardless of where it appears in the image, so the same filter slides everywhere. MLPs have neither bias — they treat every pixel independently and need to learn each position separately. This is why a CNN with 80 weights can outperform an MLP with 100,000 weights on image tasks.

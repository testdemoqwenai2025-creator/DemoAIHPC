🛠 COMPUTATIONAL TOOL · Universal File Reader

Upload Your Data

Upload any data file (CSV, TSV, JSON, TXT, Matrix Market) and the platform reads it as a binary blob, parses to a normalized Table schema (columns + rows + per-column types), shows a preview, then sends it to the heatmap + dendrogram visualiser for live clustering. Pure client-side — your data never leaves your browser. No upload to a server, no API call, no tracking. The file is read into an ArrayBuffer (the universal binary blob), then decoded by the appropriate parser based on file extension + magic-bytes detection.

📐 How it works

STEP 1File → ArrayBuffer. The browser reads the entire file as a raw binary blob (universal representation). No decoding yet — just bytes.
STEP 2Format detection. Magic-bytes sniffing (e.g., %%MatrixMarket for .mtx) + file extension → format string (csv, tsv, json, txt, mtx).
STEP 3Typed decoder. ArrayBuffer → UTF-8 string (via TextDecoder) → format-specific parser (handles quoted CSV fields, JSON shapes, Matrix Market headers, etc.).
STEP 4Type inference + coercion. Each column is scanned — if all values parse as numbers, the column is typed number; if all are true/false, boolean; otherwise string. Values are coerced to the inferred type.
STEP 5Normalized Table output: { columns, rows, types, metadata }. This is the universal schema — every downstream tool (heatmap, knowledge graph, future ML playground) speaks this shape.
STEP 6Optional binary encoding. tableToBinary() encodes the Table as a compact length-prefixed binary blob (magic bytes "AIHP" + version + flags + column/row counts + column names + per-column types + per-cell values). For large tables, this is ~50% smaller than JSON. Decoded via binaryToTable().

🔒 Privacy + data protection

ZERO UPLOADYour file is read with the browser's FileReader.readAsArrayBuffer() API. The ArrayBuffer lives only in your browser's memory. There is no fetch(), no XMLHttpRequest, no FormData. The bytes never leave your device.
NO TRACKINGNo analytics, no cookies, no fingerprinting. The page does not log which file you uploaded, what size it was, or what format. Refresh the page = everything is gone.
GDPR / HIPAABecause no PHI leaves the browser, there is no PHI to protect on the server side. The platform is GDPR-compliant and HIPAA-ready by architecture, not by policy. Hospitals can use this for pilot evaluations without a Data Processing Agreement.

Mean Squared Error (MSE) [Regression]

▾
L = (1/n) Σ_{i=1}^{n} (y_i − ŷ_i)²

MSE is the average squared difference between predicted and actual values. It penalises large errors quadratically — a 2× error gives 4× the loss. The gradient is proportional to the error magnitude, making optimisation well-behaved for convex problems.

Math → Code derivation (5 steps)

Step 1: Define the error
e_i = y_i − ŷ_i
For each sample i, the error is the difference between the true value y_i and the predicted value ŷ_i. MSE aggregates these errors across all n samples.
Step 2: Square the error
e_i² = (y_i − ŷ_i)²
Squaring removes the sign (positive and negative errors both contribute positively) and penalises large errors quadratically. A 2× error gives 4× the loss.
Step 3: Average over all samples
L = (1/n) Σ e_i²
Sum the squared errors and divide by n (the number of samples). The 1/n normalises for dataset size — a larger dataset doesn't inherently have larger loss.
Step 4: Gradient w.r.t. predictions
∂L/∂ŷ_i = −2(y_i − ŷ_i) / n = 2(ŷ_i − y_i) / n
The gradient is proportional to the error — larger errors produce larger gradients. This makes SGD converge quickly toward the correct prediction. The factor 2 comes from the chain rule on the square.
Step 5: Update rule
ŷ ← ŷ − η · ∂L/∂ŷ
Gradient descent: update the prediction by stepping against the gradient, scaled by the learning rate η. For linear regression, this converges to the OLS solution.

Mean Absolute Error (MAE) [Regression]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
L = (1/n) Σ_{i=1}^{n} |y_i − ŷ_i|

              
MAE is the average absolute difference between predicted and actual values. Unlike MSE, it penalises errors linearly — a 2× error gives 2× the loss. MAE is more robust to outliers but has a non-differentiable point at zero.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Define the error
              
e_i = y_i − ŷ_i

              
Same as MSE — the error for sample i is the difference between true and predicted values.

            

            

              Step 2: Take the absolute value
              
|e_i| = |y_i − ŷ_i|

              
Absolute value removes the sign — both positive and negative errors contribute positively. Unlike squaring, the penalty is linear, not quadratic.

            

            

              Step 3: Average over all samples
              
L = (1/n) Σ |e_i|

              
Sum the absolute errors and divide by n. The result is the mean absolute deviation.

            

            

              Step 4: Sub-gradient (non-smooth at 0)
              
∂L/∂ŷ_i = sign(ŷ_i − y_i) / n

              
The gradient is ±1/n — constant magnitude regardless of error size. This makes SGD steps uniform, but the non-differentiable point at e=0 can cause oscillation near convergence.

            

            

              Step 5: Robustness to outliers
              
MAE outlier penalty: 10× error → 10× loss (linear)

              
Unlike MSE's quadratic penalty, MAE's linear penalty means outliers don't dominate the loss. MAE is the maximum-likelihood estimator when residuals follow a Laplace distribution.

Binary Cross-Entropy (BCE) [Binary Classification]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
L = −(1/n) Σ [y_i log(ŷ_i) + (1−y_i) log(1−ŷ_i)]

              
BCE is the standard loss for binary classification. It measures the dissimilarity between the true binary distribution (y ∈ {0,1}) and the predicted probability distribution (ŷ ∈ (0,1)). The logarithm penalises confident wrong predictions heavily — a prediction of 0.01 for a true positive gives a loss of ~4.6, while a prediction of 0.49 gives only ~0.71.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Bernoulli likelihood
              
P(y | ŷ) = ŷ^y · (1−ŷ)^(1−y)

              
For a binary label y ∈ {0,1} and predicted probability ŷ ∈ (0,1), the likelihood is the Bernoulli PMF. y=1 gives P=ŷ; y=0 gives P=1−ŷ.

            

            

              Step 2: Log-likelihood
              
log P = y log(ŷ) + (1−y) log(1−ŷ)

              
Take the log to convert the product into a sum (easier to optimise). The log-likelihood is negative because log(ŷ) < 0 when ŷ < 1.

            

            

              Step 3: Negative log-likelihood (loss)
              
L = −log P = −[y log(ŷ) + (1−y) log(1−ŷ)]

              
Negate to convert maximisation into minimisation. This is the cross-entropy between the true distribution [y, 1−y] and the predicted [ŷ, 1−ŷ].

            

            

              Step 4: Average over all samples
              
L = −(1/n) Σ [y_i log(ŷ_i) + (1−y_i) log(1−ŷ_i)]

              
Sum the per-sample losses and divide by n. The 1/n normalises for batch size.

            

            

              Step 5: Gradient
              
∂L/∂ŷ_i = −(y_i/ŷ_i − (1−y_i)/(1−ŷ_i)) = (ŷ_i − y_i) / (ŷ_i(1−ŷ_i))

              
The gradient simplifies to (ŷ−y) / (ŷ(1−ŷ)). When paired with a sigmoid output, the denominator cancels the sigmoid derivative, giving a clean gradient of (ŷ−y). This is why BCE + sigmoid is the canonical binary-classification setup.

Categorical Cross-Entropy (CCE) [Multi-Class Classification]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
L = −(1/n) Σ_{i=1}^{n} Σ_{c=1}^{C} y_{ic} log(ŷ_{ic})

              
CCE is the standard loss for multi-class classification. For each sample i and class c, it compares the true one-hot label y_ic with the predicted probability ŷ_ic. Only the true class contributes (since y_ic=0 for all other classes), making the loss = −log(ŷ_true_class).

            

            
Math → Code derivation (5 steps)

            

              Step 1: Categorical likelihood
              
P(y | ŷ) = Π_c ŷ_c^{y_c}

              
For a one-hot label y (one class is 1, rest are 0) and a predicted probability distribution ŷ over C classes, the likelihood is the categorical PMF. Only the true class contributes since y_c=0 for others.

            

            

              Step 2: Log-likelihood
              
log P = Σ_c y_c log(ŷ_c)

              
Take the log. Since y is one-hot, only the true class's log-probability appears — log P = log(ŷ_true).

            

            

              Step 3: Negative log-likelihood (loss)
              
L = −Σ_c y_c log(ŷ_c) = −log(ŷ_true)

              
Negate to convert maximisation into minimisation. The loss is just the negative log-probability of the true class.

            

            

              Step 4: Average over all samples
              
L = −(1/n) Σ_i Σ_c y_{ic} log(ŷ_{ic})

              
Sum over all samples and classes. The one-hot structure means only the true class per sample contributes.

            

            

              Step 5: Gradient with softmax
              
∂L/∂z_c = ŷ_c − y_c

              
When paired with a softmax output, the gradient of the loss w.r.t. the pre-activation z_c simplifies to (ŷ_c − y_c) — the prediction error. This clean gradient is why CCE + softmax is the canonical multi-class setup.

Hinge Loss [SVM / Max-Margin]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
L = (1/n) Σ_{i=1}^{n} max(0, 1 − y_i · ŷ_i)

              
Hinge loss is used in Support Vector Machines (SVMs). Labels y ∈ {−1, +1}; predictions ŷ are raw scores (not probabilities). The loss is zero when y·ŷ ≥ 1 (correct with margin), and linear when y·ŷ < 1. The 'hinge' shape encourages a margin of at least 1 between classes.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Label convention
              
y ∈ {−1, +1},  ŷ ∈ ℝ (raw score)

              
SVM uses ±1 labels (not 0/1) and raw scores (not probabilities). A correct prediction with margin has y·ŷ ≥ 1.

            

            

              Step 2: Margin condition
              
y · ŷ ≥ 1  →  correct with margin

              
The product y·ŷ measures both correctness and confidence. If positive, the prediction is in the right direction. If ≥ 1, the prediction has sufficient margin.

            

            

              Step 3: Hinge function
              
L_i = max(0, 1 − y_i · ŷ_i)

              
The loss is zero when the margin is met (y·ŷ ≥ 1), and grows linearly when the margin is violated. The 'hinge' is the kink at y·ŷ = 1.

            

            

              Step 4: Average over all samples
              
L = (1/n) Σ max(0, 1 − y_i · ŷ_i)

              
Sum the per-sample hinge losses and divide by n. Samples with margin > 1 contribute zero — they don't affect the loss.

            

            

              Step 5: Sub-gradient
              
∂L/∂ŷ_i = −y_i  if y_i·ŷ_i < 1,  else 0

              
The gradient is −y for margin-violating samples (constant magnitude), and 0 for samples with sufficient margin. This makes SVM training focus only on the 'support vectors' — the samples near the margin.

Log-Cosh Loss [Regression]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
L = (1/n) Σ_{i=1}^{n} log(cosh(ŷ_i − y_i))

              
Log-Cosh is a smooth approximation to MSE that behaves like MSE for small errors and like MAE for large errors. It's twice differentiable everywhere (unlike MAE), making it suitable for Newton-style optimisation (e.g. XGBoost). The name comes from log(cosh(x)) ≈ x²/2 for small x and ≈ |x| − log(2) for large x.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Cosh function
              
cosh(x) = (e^x + e^(−x)) / 2

              
The hyperbolic cosine is a smooth even function — cosh(−x) = cosh(x). It grows exponentially for large |x|.

            

            

              Step 2: Log of cosh
              
log(cosh(x))

              
Taking the log converts exponential growth back to linear growth. For small x: log(cosh(x)) ≈ x²/2. For large x: log(cosh(x)) ≈ |x| − log(2).

            

            

              Step 3: Loss definition
              
L = (1/n) Σ log(cosh(ŷ_i − y_i))

              
Average the log-cosh of the errors over all samples. Small errors give quadratic loss (like MSE); large errors give linear loss (like MAE).

            

            

              Step 4: Gradient
              
∂L/∂ŷ_i = tanh(ŷ_i − y_i) / n

              
The gradient is tanh(error)/n — bounded by ±1/n. For small errors, tanh(e) ≈ e (MSE-like gradient). For large errors, tanh(e) → ±1 (MAE-like constant gradient).

            

            

              Step 5: Hessian (for Newton methods)
              
∂²L/∂ŷ² = sech²(ŷ − y) / n = 1 / (n·cosh²(ŷ − y))

              
The Hessian is always positive and bounded — it's the square of the gradient of tanh. This makes log-cosh twice-differentiable, suitable for Newton-Raphson optimisation (used in XGBoost).

Huber Loss [Robust Regression]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
L_δ(e) = { ½e²  if |e| ≤ δ;  δ(|e| − ½δ)  if |e| > δ }

              
Huber loss is quadratic (MSE-like) for small errors and linear (MAE-like) for large errors, with a configurable threshold δ. It's the canonical robust-regression loss — less sensitive to outliers than MSE, but smoother than MAE (differentiable everywhere). δ controls the transition point.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Define the error
              
e_i = y_i − ŷ_i

              
Same as MSE/MAE — the error for sample i is the difference between true and predicted values.

            

            

              Step 2: Quadratic region (|e| ≤ δ)
              
L = ½ e²

              
For small errors (within the threshold δ), the loss is quadratic — same as MSE. This gives fast convergence near the optimum.

            

            

              Step 3: Linear region (|e| > δ)
              
L = δ(|e| − ½δ)

              
For large errors (beyond δ), the loss is linear — same as MAE. This caps the influence of outliers: a 10× outlier gives the same gradient as a 2× outlier (both are δ).

            

            

              Step 4: Piecewise definition
              
L_δ(e) = { ½e²  if |e| ≤ δ;  δ(|e| − ½δ)  if |e| > δ }

              
The two regions are continuous at |e| = δ: ½δ² = δ(δ − ½δ) = ½δ². The gradient transitions from e (quadratic) to δ·sign(e) (linear) at the threshold.

            

            

              Step 5: Choosing δ
              
δ = 1.0 (default) or σ·1.345 (Mad) 

              
δ controls the transition. A common heuristic is δ = 1.345·σ (where σ is the residual standard deviation) — this gives 95% efficiency under Gaussian noise while remaining robust to outliers. Smaller δ → more robust (like MAE); larger δ → more sensitive (like MSE).

KL Divergence [Probability Distributions]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
D_KL(P || Q) = Σ_x P(x) log(P(x) / Q(x))

              
KL divergence measures the dissimilarity between two probability distributions P (true) and Q (predicted). It's not symmetric (D_KL(P||Q) ≠ D_KL(Q||P)) and is always ≥ 0 (Gibbs' inequality). KL is used in VAEs (as the regularisation term), in knowledge distillation (matching teacher-student distributions), and in variational inference.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Two distributions
              
P(x) = true distribution,  Q(x) = predicted distribution

              
Both P and Q are probability distributions over the same support: Σ P(x) = 1, Σ Q(x) = 1, P(x) ≥ 0, Q(x) ≥ 0.

            

            

              Step 2: Log-ratio
              
log(P(x) / Q(x)) = log P(x) − log Q(x)

              
The log-ratio measures how much more likely x is under P than under Q. If P(x) > Q(x), the ratio is positive (P assigns more mass). If P(x) < Q(x), the ratio is negative.

            

            

              Step 3: Expectation under P
              
D_KL(P || Q) = E_P[log(P/Q)] = Σ P(x) log(P(x)/Q(x))

              
The KL divergence is the expected log-ratio under the true distribution P. The expectation weights each x by P(x) — so only where P has mass does the divergence change.

            

            

              Step 4: Non-negativity (Gibbs' inequality)
              
D_KL(P || Q) ≥ 0,  with equality iff P = Q

              
By Jensen's inequality applied to the convex function −log: D_KL = E_P[log(P/Q)] = −E_P[log(Q/P)] ≥ −log(E_P[Q/P]) = −log(1) = 0. Equality holds iff P = Q everywhere.

            

            

              Step 5: Asymmetry + relation to cross-entropy
              
D_KL(P||Q) = H(P,Q) − H(P),  H(P,Q) = −Σ P log Q

              
KL = cross-entropy − entropy. Minimising cross-entropy (the standard classification loss) is equivalent to minimising KL (since H(P) is constant for fixed labels). This is why CCE is the MLE.

Cosine Similarity Loss [Embeddings]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
L = 1 − (A · B) / (||A|| · ||B||) = 1 − cos(θ)

              
Cosine similarity measures the angle between two vectors, ignoring their magnitude. The loss is 1 minus the cosine similarity — 0 when vectors are parallel, 1 when orthogonal, 2 when anti-parallel. Used in embedding learning (e.g. sentence-BERT, CLIP) where the direction matters more than the magnitude.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Dot product
              
A · B = Σ A_i B_i = ||A|| ||B|| cos(θ)

              
The dot product of two vectors equals the product of their magnitudes times the cosine of the angle between them. This is the geometric definition.

            

            

              Step 2: Normalise by magnitudes
              
cos(θ) = (A · B) / (||A|| ||B||)

              
Dividing by the magnitudes normalises the dot product to the range [−1, 1], independent of vector length. cos(0°)=1 (parallel), cos(90°)=0 (orthogonal), cos(180°)=−1 (anti-parallel).

            

            

              Step 3: Cosine similarity
              
sim(A, B) = cos(θ) = (A · B) / (||A|| ||B||)

              
Cosine similarity = the normalised dot product. High value = vectors point in the same direction (semantically similar for embeddings).

            

            

              Step 4: Loss = 1 − similarity
              
L = 1 − cos(θ) = 1 − (A · B) / (||A|| ||B||)

              
Convert similarity (high = good) to loss (low = good) by subtracting from 1. L=0 when parallel, L=1 when orthogonal, L=2 when anti-parallel.

            

            

              Step 5: Gradient
              
∂L/∂A = −B / (||A|| ||B||) + (A · B) A / (||A||³ ||B||)

              
The gradient has two terms: one pushing A toward B (alignment) and one regularising A's magnitude (since cosine is scale-invariant, the gradient is perpendicular to A).

ReLU (Rectified Linear Unit) [Activation Function]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
f(x) = max(0, x)

              
ReLU is the most widely used activation function in deep learning. It outputs 0 for negative inputs and the identity for positive inputs. ReLU is computationally cheap (a single max operation), sparse-activating (many neurons output 0), and non-saturating for positive gradients (no vanishing gradient for x > 0).

            

            
Math → Code derivation (5 steps)

            

              Step 1: Define the function
              
f(x) = max(0, x)

              
For any input x, output 0 if x < 0, else output x. This is a piecewise linear function with a kink at x = 0.

            

            

              Step 2: Gradient
              
f'(x) = 1 if x > 0, 0 if x < 0, undefined at x = 0

              
The gradient is 1 for positive inputs (no vanishing gradient) and 0 for negative inputs (dead neurons). At x = 0, the sub-gradient is used (typically 0 or 1).

            

            

              Step 3: Sparsity
              
P(f(x) = 0) = P(x < 0)

              
For normally-distributed inputs, ~50% of neurons output 0. This sparsity is computationally efficient and acts as implicit regularisation.

            

            

              Step 4: Non-saturating
              
For x > 0: f'(x) = 1 (constant gradient)

              
Unlike sigmoid/tanh whose gradients vanish as x grows, ReLU's gradient is 1 for all positive x. This enables training very deep networks.

            

            

              Step 5: Dead neuron problem
              
If x < 0 for all training data: f'(x) = 0, neuron never recovers

              
A 'dead ReLU' outputs 0 and has 0 gradient for all inputs — it never updates. Mitigated by Leaky ReLU (f(x) = max(αx, x) for small α) or careful initialisation.

GELU (Gaussian Error Linear Unit) [Activation Function]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
f(x) = x * Phi(x) approx 0.5x(1 + tanh(sqrt(2/pi)(x + 0.044715x^3)))

              
GELU is a smooth approximation of ReLU that multiplies the input by its own Gaussian CDF. For large positive x, f(x) approx x (like ReLU). For large negative x, f(x) approx 0 (like ReLU). Near x=0, GELU is smooth (no kink), giving it better gradient properties than ReLU.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Gaussian CDF
              
Phi(x) = integral from -inf to x of (1/sqrt(2*pi)) * exp(-t^2/2) dt

              
Phi(x) is the cumulative distribution function of the standard normal. It is 0 for very negative x, 0.5 at x=0, and 1 for very positive x.

            

            

              Step 2: GELU definition
              
f(x) = x * Phi(x)

              
Multiply the input by its own CDF. For x >> 0: Phi approx 1, so f(x) approx x. For x << 0: Phi approx 0, so f(x) approx 0. Near x=0: smooth transition.

            

            

              Step 3: Tanh approximation
              
Phi(x) approx 0.5 * (1 + tanh(sqrt(2/pi) * (x + 0.044715 * x^3)))

              
The exact Phi requires the error function (erf). The tanh approximation is accurate to within 0.0001 and is much faster to compute.

            

            

              Step 4: Gradient
              
f'(x) = Phi(x) + x * phi(x)

              
where phi(x) is the Gaussian PDF. The gradient is smooth everywhere (no kink), and non-zero for x < 0 (unlike ReLU).

            

            

              Step 5: Why it works
              
GELU is dropout-like (probabilistic) + ReLU-like (deterministic)

              
GELU can be interpreted as 'ReLU with soft gating': instead of a hard 0/1 gate, it uses a probabilistic gate Phi(x). This smoothness improves generalisation and is the default activation in BERT, GPT, and most transformer models.

SwiGLU (Swish-Gated Linear Unit) [Activation Function]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
f(x, W) = Swish(x) * (xW + b),  where Swish(x) = x * sigmoid(x)

              
SwiGLU is a gated activation used in modern LLMs (LLaMA, PaLM 2). It combines the Swish activation (x * sigma(x)) with a learned linear projection (xW + b). The Swish part acts as a smooth gate that controls how much of the linear projection passes through. SwiGLU outperforms ReLU and GELU in large language models.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Swish activation
              
Swish(x) = x * sigmoid(x) = x / (1 + exp(-x))

              
Swish is a smooth, non-monotonic activation. For x >> 0: Swish approx x (linear). For x << 0: Swish approx 0. Near x = 0: Swish has a slight dip (non-monotonic), which helps with feature selection.

            

            

              Step 2: Gated linear unit
              
GLU(x, W) = sigmoid(xW) * (xV)

              
GLU gates a linear projection xV by a sigmoid gate sigma(xW). SwiGLU replaces the sigmoid gate with Swish: SwiGLU = Swish(xW) * (xV).

            

            

              Step 3: SwiGLU definition
              
SwiGLU(x, W, V) = Swish(xW) * (xV)

              
Two learned projections: W (gate) and V (value). The Swish gate controls how much of xV passes through. The gate is smooth (unlike GLU's hard sigmoid).

            

            

              Step 4: Gradient
              
d(SwGLU)/d(xV) = Swish(xW)

              
The gradient w.r.t. the value path is the Swish gate — smooth and non-zero for all x. The gradient w.r.t. the gate path involves Swish' = sigma(x) + x * sigma'(x).

            

            

              Step 5: Performance
              
SwiGLU > GELU > ReLU in LLM training (LLaMA, PaLM 2)

              
Empirically, SwiGLU gives better perplexity than GELU and ReLU in transformer LLMs. The non-monotonicity of Swish + the learned gate provides richer feature selection. Used in LLaMA-2/3, PaLM 2, and Mistral.

SGD (Stochastic Gradient Descent) [Optimiser]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
theta <- theta - eta * grad_L(theta)

              
SGD is the simplest optimiser: update parameters by stepping against the gradient, scaled by the learning rate eta. The 'stochastic' part comes from using mini-batches (not the full dataset) to estimate the gradient, introducing noise that helps escape local minima.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Loss gradient
              
grad = dL/d(theta)

              
Compute the gradient of the loss w.r.t. parameters. In practice, this is done on a mini-batch of data (not the full dataset), introducing stochastic noise.

            

            

              Step 2: Update rule
              
theta_new = theta - eta * grad

              
Step against the gradient by a distance proportional to eta (the learning rate). eta controls the step size; too large = unstable, too small = slow convergence.

            

            

              Step 3: Learning rate schedule
              
eta_t = eta_0 / (1 + decay * t)

              
Decay the learning rate over time to allow large steps early (fast convergence) and small steps later (fine-tuning). Common schedules: step decay, cosine annealing, warmup + constant.

            

            

              Step 4: Mini-batch noise
              
E[grad_batch] = grad_true, Var[grad_batch] ~ 1/batch_size

              
The mini-batch gradient is an unbiased estimator of the true gradient, with variance inversely proportional to batch size. The noise helps escape saddle points and shallow local minima.

            

            

              Step 5: Convergence
              
For convex L: O(1/sqrt(t)) with eta = 1/sqrt(t)

              
SGD converges to the global minimum for convex losses. For non-convex (deep networks), convergence is not guaranteed, but SGD reliably finds good local minima in practice.

Adam (Adaptive Moment Estimation) [Optimiser]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
m_t = beta1*m + (1-beta1)*g;  v_t = beta2*v + (1-beta2)*g^2;  theta <- theta - eta * m_hat / (sqrt(v_hat) + eps)

              
Adam combines momentum (exponential moving average of gradients, like SGD+Momentum) with RMSProp (exponential moving average of squared gradients). The ratio m/sqrt(v) gives an adaptive per-parameter learning rate: parameters with large consistent gradients get smaller steps, parameters with small or rare gradients get larger steps.

            

            
Math → Code derivation (5 steps)

            

              Step 1: First moment (momentum)
              
m_t = beta1 * m_{t-1} + (1 - beta1) * g_t

              
Exponential moving average of gradients. beta1 = 0.9 (default). Smooths noisy gradients — acts as momentum.

            

            

              Step 2: Second moment (RMSProp)
              
v_t = beta2 * v_{t-1} + (1 - beta2) * g_t^2

              
Exponential moving average of squared gradients. beta2 = 0.999 (default). Estimates the per-parameter gradient magnitude.

            

            

              Step 3: Bias correction
              
m_hat = m_t / (1 - beta1^t);  v_hat = v_t / (1 - beta2^t)

              
The EMA is biased toward 0 in early iterations (since m_0 = v_0 = 0). Dividing by (1 - beta^t) corrects this — important for the first few hundred steps.

            

            

              Step 4: Update
              
theta <- theta - eta * m_hat / (sqrt(v_hat) + eps)

              
The step size is eta * (smoothed gradient) / (smoothed gradient magnitude). This gives large steps for rare-but-consistent gradients and small steps for frequent-but-noisy gradients. eps = 1e-8 prevents division by zero.

eta=1e-3, beta1=0.9, beta2=0.999, eps=1e-8

              
Adam's defaults work well for most problems without tuning. This is a key practical advantage over SGD (which requires careful eta tuning + schedule).

AdamW (Adam with Decoupled Weight Decay) [Optimiser]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
Same as Adam + theta <- theta - eta * wd * theta (decoupled from gradient)

              
AdamW fixes a subtle issue in Adam's L2 regularisation: in standard Adam, weight decay is coupled with the gradient (wd * grad), which interacts with the adaptive learning rate in unintended ways. AdamW decouples weight decay from the gradient update, applying it directly to the parameters. This gives better generalisation, especially for transformers.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Adam's L2 issue
              
In Adam, L2 reg adds wd*theta to the gradient: g' = g + wd*theta

              
L2 regularisation is implemented by adding wd*theta to the gradient before computing the moments. But Adam's adaptive denominator (sqrt(v)) interacts with this: the weight decay gets scaled differently for each parameter.

            

            

              Step 2: Coupled vs decoupled
              
Coupled: g' = g + wd*theta (Adam).  Decoupled: theta -= eta*wd*theta (AdamW)

              
AdamW applies weight decay directly to theta, NOT through the gradient. This makes the weight decay equivalent across all parameters — independent of the adaptive learning rate.

            

            

              Step 3: AdamW update
              
1. Compute Adam moments (m, v) from g (WITHOUT wd*theta)
2. theta <- theta - eta*wd*theta (decoupled weight decay)
3. theta <- theta - eta * m_hat / sqrt(v_hat + eps) (Adam step)

              
The weight decay is a simple multiplication (step 2), applied BEFORE the Adam gradient step (step 3). This is mathematically equivalent to L2 for SGD but different for Adam.

            

            

              Step 4: Why it matters for transformers
              
Transformers need large weight decay (0.1) for generalisation

              
In standard Adam, the large weight decay gets distorted by the adaptive learning rate. AdamW's decoupled decay applies uniformly, enabling the large wd=0.1 that transformers need.

            

            

              Step 5: Default hyperparameters
              
eta=1e-3, beta1=0.9, beta2=0.999, wd=0.01 (vision) / 0.1 (NLP)

              
AdamW's weight decay is typically 0.01 for CNNs (ResNet) and 0.1 for transformers (BERT, ViT). The higher wd for transformers prevents overfitting on large datasets.

Dropout [Regularisation]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
y = x * mask,  where mask[i] ~ Bernoulli(1-p) / (1-p)

              
Dropout randomly sets a fraction p of activations to zero during training, forcing the network to learn redundant representations. At inference, all activations are used (scaled by 1/(1-p) during training to compensate). Dropout prevents co-adaptation: no single neuron can rely on any other specific neuron being active.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Mask generation
              
mask[i] ~ Bernoulli(1 - p)

              
For each neuron, draw a random binary mask: 1 with probability (1-p), 0 with probability p. p is the dropout rate (typically 0.1-0.5).

            

            

              Step 2: Apply mask
              
y = x * mask

              
Element-wise multiply the activations by the mask. p fraction of neurons are 'dropped' (output 0). The surviving neurons must learn to function without the dropped ones.

            

            

              Step 3: Inverted dropout (scaling)
              
y = x * mask / (1 - p)

              
Divide by (1-p) during training so that the expected output E[y] = x. This 'inverted dropout' means no scaling is needed at inference time — just use y = x (all neurons active).

            

            

              Step 4: Preventing co-adaptation
              
Each neuron must work with random subsets of others

              
Since any neuron can be dropped, no two neurons can co-adapt (rely on each other). The network learns redundant, robust features — like training an ensemble of sub-networks in one pass.

            

            

              Step 5: Inference
              
At test time: y = x (no dropout, no scaling needed)

              
Thanks to inverted dropout (step 3), inference is just the identity — all neurons active, no scaling. The network behaves as an ensemble of the 2^N sub-networks sampled during training.

L1/L2 Regularisation (Weight Decay) [Regularisation]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
L_reg = L_data + lambda1 * ||w||_1 + lambda2 * ||w||_2^2

              
L1 and L2 regularisation add a penalty term to the loss function: L1 (sum of |w|) encourages sparsity (many weights -> 0), L2 (sum of w^2) encourages small weights. The regularisation parameter lambda controls the strength: larger lambda = more regularisation (simpler model).

            

            
Math → Code derivation (5 steps)

            

              Step 1: L2 (Ridge) penalty
              
L2 = lambda * sum(w^2) = lambda * ||w||_2^2

              
L2 adds lambda * ||w||^2 to the loss. The gradient is 2*lambda*w — proportional to the weight. This shrinks all weights toward 0 smoothly. No weight becomes exactly 0.

            

            

              Step 2: L1 (Lasso) penalty
              
L1 = lambda * sum(|w|) = lambda * ||w||_1

              
L1 adds lambda * sum(|w|) to the loss. The gradient is lambda * sign(w) — constant magnitude. This can drive weights to exactly 0 (sparsity), enabling feature selection.

            

            

              Step 3: L1 sparsity
              
L1 gradient = lambda * sign(w) — constant magnitude

              
Because the L1 gradient is constant (lambda * sign(w)), weights near 0 get pushed to exactly 0. This is unlike L2 whose gradient (2*lambda*w) -> 0 as w -> 0, leaving small but non-zero weights.

            

            

              Step 4: Elastic net (L1 + L2)
              
L_reg = L + lambda1 * ||w||_1 + lambda2 * ||w||_2^2

              
Elastic net combines L1 (sparsity) + L2 (smoothness). Useful when features are correlated — L1 alone picks one, L2 keeps all small; elastic net keeps groups.

            

            

              Step 5: Weight decay vs L2
              
Weight decay: theta <- theta - eta * (grad + lambda * theta) = theta * (1 - eta*lambda) - eta*grad

              
Weight decay is the gradient-descent form of L2: the weight is shrunk by a factor (1 - eta*lambda) at each step. For SGD, this is equivalent to L2. For Adam, see AdamW (decoupled weight decay).

Batch Normalisation [Regularisation]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
y = gamma * (x - mu_B) / sqrt(sigma_B^2 + eps) + beta

              
BatchNorm normalises each layer's activations to have zero mean and unit variance (per mini-batch), then applies a learned scale (gamma) and shift (beta). This stabilises training, allows higher learning rates, and acts as mild regularisation (batch noise). BatchNorm was a key enabler of training very deep networks (ResNet).

            

            
Math → Code derivation (5 steps)

            

              Step 1: Batch statistics
              
mu_B = (1/m) * sum(x_i);  sigma_B^2 = (1/m) * sum((x_i - mu_B)^2)

              
Compute the mean and variance of the activations over the mini-batch of size m. These statistics are different for each batch — introducing stochastic noise.

            

            

              Step 2: Normalise
              
x_hat = (x - mu_B) / sqrt(sigma_B^2 + eps)

              
Subtract the batch mean and divide by the batch std. eps = 1e-5 prevents division by zero. The result has zero mean and unit variance (per batch).

            

            

              Step 3: Learnable scale + shift
              
y = gamma * x_hat + beta

              
gamma and beta are learned parameters that allow the network to undo the normalisation if it's not helpful. Without gamma/beta, BatchNorm would force every layer to have unit variance — too restrictive.

            

            

              Step 4: Running statistics (inference)
              
mu_running = alpha * mu_running + (1-alpha) * mu_B

              
During training, keep a running average of mu_B and sigma_B. At inference, use the running averages instead of batch statistics (since inference may have batch size 1).

            

            

              Step 5: Why it works
              
Reduces internal covariate shift + enables higher lr + mild regularisation

              
BatchNorm stabilises the distribution of activations across layers, reducing 'internal covariate shift'. This allows 10x higher learning rates and faster convergence. The batch-level noise also acts as mild regularisation (reducing the need for dropout).

Scaled Dot-Product Attention [Attention]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
Attention(Q, K, V) = softmax( (Q·K^T) / sqrt(d_k) ) · V

              
The foundational attention mechanism behind every Transformer. We project the query Q against every key K (dot product), scale by 1/sqrt(d_k) to prevent the softmax saturating for large d_k, apply softmax to get attention weights, and use them as weights over the value vectors V. The result is a context-aware blend of V where each query element focuses on the keys most relevant to it.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Dot-product Q against K
              
scores = Q · K^T  (shape: [seq_q, seq_k])

              
For each query position, compute the similarity (dot product) against every key position. A high dot product means the query and key vectors point in the same direction in the embedding space.

            

            

              Step 2: Scale by 1/sqrt(d_k)
              
scaled = scores / sqrt(d_k)

              
If d_k is large, dot products can be huge, which pushes softmax into regions with very small gradients (saturation). Dividing by sqrt(d_k) keeps the variance of the scores ~1 regardless of dimension.

            

            

              Step 3: Softmax over keys
              
weights = softmax(scaled, axis=keys)

              
Apply softmax along the key axis so each row of weights sums to 1. This converts raw scores into a probability distribution over keys — the query 'attends' to keys proportional to their scaled similarity.

            

            

              Step 4: Weighted sum of V
              
output = weights · V

              
For each query, compute a weighted average of value vectors using the attention weights. The result is a length-d_v context vector per query position — a soft, learned retrieval over the (K, V) memory.

            

            

              Step 5: Why this works
              
Differentiable, content-based addressing

              
Unlike hard retrieval (one-hot argmax), softmax is differentiable everywhere — gradients flow back to Q, K, and V. This makes attention trainable end-to-end and is the core innovation that enabled Transformers.

Multi-Head Attention [Attention]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
MultiHead(Q,K,V) = Concat(head_1, ..., head_h) W_O;  head_i = Attention(Q W_i^Q, K W_i^K, V W_i^V)

              
Instead of a single attention with d_model-dim queries/keys/values, split into h parallel heads each with d_model/h dimensions. Each head learns a different attention pattern — head 1 might attend to syntax, head 2 to coreference, head 3 to entity types, etc. The outputs are concatenated and projected back to d_model with W_O.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Linear projections per head
              
Q_i = Q · W_i^Q, K_i = K · W_i^K, V_i = V · W_i^V

              
Project the d_model-dim Q, K, V to d_k = d_model/h dimensions per head. Each head has its own learned projection matrices W_i^Q, W_i^K, W_i^V — this is what allows heads to specialise.

            

            

              Step 2: Independent attention per head
              
head_i = Attention(Q_i, K_i, V_i)

              
Each head runs the standard scaled dot-product attention in parallel. The h attention patterns are computed independently — no communication between heads during the forward pass.

            

            

              Step 3: Concatenate heads
              
concat = [head_1; head_2; ...; head_h]

              
Stack the h outputs of shape [seq, d_v] along the feature axis to get [seq, h*d_v]. Since d_v = d_model/h, this concatenation restores the d_model dimension.

            

            

              Step 4: Output projection
              
output = concat · W_O

              
Apply a learned projection W_O of shape [d_model, d_model] to mix the information from all heads. This projection is what lets the model combine head outputs (e.g., 'head 2 said token is a verb, head 5 says it agrees with subject').

            

            

              Step 5: Cost / benefit
              
Same FLOPs as single-head (h heads * d_model/h dim = d_model)

              
Multi-head has approximately the same compute cost as single-head attention with full dimension. The benefit is that heads can specialise — empirically, heads learn to track syntax, coreference, rare words, etc. Ablating individual heads often barely affects performance, suggesting redundancy.

FlashAttention [Attention]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
Attention(Q,K,V) computed via tiling + online-softmax — never materialises the full N×N matrix

              
FlashAttention (Dao et al. 2022) computes the exact same attention as scaled dot-product, but reorders the computation to avoid materialising the full N×N attention matrix in HBM. Instead, it loads tiles of Q, K, V into SRAM, computes a partial softmax that can be merged incrementally ('online softmax'), and writes only the final output back. Result: same numbers, 2-4x faster, 10x less memory.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Tiling
              
Load Q[i:i+B_q], K[j:j+B_k], V[j:j+B_k] into SRAM

              
GPU SRAM (~192KB/SM) is 100x faster than HBM (~3TB/s, 80GB). Standard attention writes the full NxN score matrix to HBM then reads it back for softmax. FlashAttention instead processes Q,K,V in tiles that fit in SRAM.

            

            

              Step 2: Online softmax
              
m_new = max(m_old, m_tile); s_new = exp(m_old - m_new) * s_old + sum(exp(s_tile - m_new))

              
Normally softmax needs the max over the full row. 'Online softmax' (Milan Puzic / Nikolay Dryden) shows we can update the running max and running sum incrementally as we see each K tile. This is the key trick that makes attention tileable.

            

            

              Step 3: Partial output
              
o_partial = sum(exp(s_tile - m_new)) * V_tile / s_new

              
For each K tile, compute the partial weighted sum of V. Maintain the running normaliser s_new so the partial output can be correctly reweighted when new tiles arrive.

            

            

              Step 4: Recompute backward
              
Recompute attention in backward pass instead of storing the N×N matrix

              
Standard autograd stores the N×N softmax weights for the backward pass. FlashAttention recomputes them — trades compute for memory. Since SRAM is so fast, the recompute is faster than the saved HBM I/O.

            

            

              Step 5: Why it matters
              
10x memory → enables 32K context GPT, training not possible otherwise

              
Standard attention at seq=32K needs ~4GB just for the score matrix. FlashAttention needs ~512MB — enabling long-context LLMs (GPT-4 128K, Claude 200K, Gemini 1M). The exact same mathematics, just reordered for the memory hierarchy.

Layer Normalisation [Normalisation]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
y = gamma * (x - mu) / sqrt(sigma^2 + eps) + beta  where mu = mean over feature axis

              
LayerNorm normalises each token's feature vector independently — the mean and variance are computed across the feature axis (not the batch axis like BatchNorm). This makes LayerNorm independent of batch size and works identically at train and inference — a key advantage for transformers and RNNs where batch size varies.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Per-token statistics
              
mu = mean(x over feature axis);  sigma^2 = var(x over feature axis)

              
For each token in each sample, compute the mean and variance across the d_model features. Unlike BatchNorm (statistics over batch), LayerNorm statistics are per-token — no batch dependency.

            

            

              Step 2: Normalise
              
x_hat = (x - mu) / sqrt(sigma^2 + eps)

              
Subtract the per-token mean and divide by the per-token std. eps = 1e-5 prevents division by zero. The result has zero mean and unit variance per token — stabilises gradient flow through deep stacks.

            

            

              Step 3: Affine transform
              
y = gamma * x_hat + beta

              
gamma and beta are learned per-feature parameters. They allow the network to undo normalisation if unhelpful (gamma = sqrt(sigma^2), beta = mu recovers x). Without the affine, every layer's output would be forced to unit variance.

            

            

              Step 4: Inference (no running stats needed)
              
Same as training — mu and sigma^2 computed on the fly

              
Unlike BatchNorm (which needs running averages for inference), LayerNorm uses live statistics. This means batch size 1 works at inference and there's no train/test mismatch.

            

            

              Step 5: Why Transformers use it
              
Stable through 100+ layers + no batch dependency

              
LayerNorm is the standard normaliser for Transformers because (a) it stabilises gradients through 100+ stacked attention+MLP blocks, (b) it doesn't depend on batch size — critical for inference and gradient accumulation, (c) it works in autoregressive decoding where 'batch' is one token. RMSNorm is a popular simplification (drop the mean-centering).

RMS Normalisation [Normalisation]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
y = gamma * x / sqrt(mean(x^2) + eps)  — no mean-centering, no beta

              
RMSNorm (Zhang & Sennrich 2019) is a simplification of LayerNorm: drop the mean-centering (no subtraction of mu) and drop the bias term beta. Only the root-mean-square (RMS) is used to scale. Empirically works as well as LayerNorm at slightly lower compute cost (no mean computation). Used in Llama, Qwen, Mistral, Gemma.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Compute RMS (no mean!)
              
rms = sqrt( (1/d) * sum(x_i^2) )

              
Root-mean-square of the feature vector. This is just the L2 norm scaled by 1/sqrt(d). Skipping the mean-centering saves one reduction — slightly less compute than LayerNorm.

            

            

              Step 2: Scale
              
x_hat = x / (rms + eps)

              
Divide each feature by the RMS. The output has RMS = 1 (regardless of input scale). No mean-centering means the output preserves the sign of the input — the relative pattern is unchanged.

            

            

              Step 3: Affine (gamma only)
              
y = gamma * x_hat

              
Only a learned scale gamma per feature — no beta. The intuition: mean-centering and beta are mostly redundant — gamma alone can re-scale to any desired variance; the mean shift is rarely needed.

            

            

              Step 4: No beta
              
Drop beta — saves params + FLOPs

              
Removing beta halves the affine params and removes one addition. Empirically, models with RMSNorm match LayerNorm-trained models within noise. The slight compute saving compounds across 100+ layers and trillions of tokens.

            

            

              Step 5: Why Llama uses it
              
Same quality, slightly faster, simpler code

              
Llama, Qwen, Mistral, Gemma, DeepSeek all use RMSNorm. The reason: LayerNorm's mean-centering adds compute without measurable quality benefit. RMSNorm is the de-facto normaliser for production LLMs since 2023.

Group Normalisation [Normalisation]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
y = gamma * (x - mu_g) / sqrt(sigma_g^2 + eps) + beta  where mu_g, sigma_g^2 over groups of channels

              
GroupNorm (Wu & He 2018) is the middle ground between LayerNorm (normalise all features per token) and InstanceNorm (normalise each feature independently). Features are split into G groups; statistics are computed within each group. This is the natural normaliser for CNNs with small batch sizes (e.g. detection/segmentation where batch=1-2 per GPU) where BatchNorm fails.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Reshape features into G groups
              
x reshaped to [B, G, C/G, H, W]

              
Take a tensor of shape [B, C, H, W] and reshape the C channels into G groups of C/G channels each. Typical G = 32 — each group contains C/32 channels that are normalised together.

            

            

              Step 2: Compute group statistics
              
mu_g = mean over (C/G, H, W);  sigma_g^2 = var over (C/G, H, W)

              
For each sample B and each group g, compute the mean and variance across all C/G channels and all spatial positions H,W. The statistics are independent of batch — GroupNorm works at any batch size.

            

            

              Step 3: Normalise
              
x_hat = (x - mu_g) / sqrt(sigma_g^2 + eps)

              
Each element is normalised by its group's statistics. Channels within the same group share stats — providing cross-channel information sharing. Different groups have independent stats — providing diversity.

            

            

              Step 4: Affine
              
y = gamma * x_hat + beta  (per channel)

              
gamma and beta are learned per-channel (not per-group). This allows each channel to re-scale and re-shift independently — critical because different channels may encode different feature types (edges, textures, colors).

            

            

              Step 5: When to use
              
CNNs with small batch (detection, segmentation, video)

              
BatchNorm fails when batch size is small (≤4) — batch statistics are noisy. GroupNorm is batch-independent, making it ideal for object detection (Fast/Faster R-CNN train at batch=2/GPU), segmentation (U-Net batch=1), and video (3D CNNs with tiny batches).

Instance Normalisation [Normalisation]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
y = gamma * (x - mu_c) / sqrt(sigma_c^2 + eps) + beta  where mu_c per-sample per-channel

              
InstanceNorm (Ulyanov et al. 2016) normalises each channel of each sample independently — like a per-channel LayerNorm but with statistics computed per-sample-per-channel (over the spatial axes only). Originally designed for style transfer — InstanceNorm normalises image contrast/style without normalising content. Now also used in GANs (BigGAN, StyleGAN) and diffusion models (DDPM).

            

            
Math → Code derivation (5 steps)

            

              Step 1: Per-sample per-channel stats
              
mu_c = mean(x over H, W);  sigma_c^2 = var(x over H, W)

              
For each sample B and each channel C, compute the mean and variance over the spatial axes (H, W). The statistics are independent of batch and independent across channels — each (B, C) pair has its own stats.

            

            

              Step 2: Normalise
              
x_hat = (x - mu_c) / sqrt(sigma_c^2 + eps)

              
Each element is normalised by its channel's statistics. The output has zero mean and unit variance per (B, C) — image content (relative structure) is preserved, but absolute contrast (per-channel scale) is removed.

            

            

              Step 3: Affine
              
y = gamma * x_hat + beta  (per channel, optional)

              
Unlike BatchNorm where affine is critical, InstanceNorm's affine is often dropped (e.g. in StyleGAN where gamma/beta come from style modulation). When present, gamma/beta are per-channel.

            

            

              Step 4: Style transfer insight
              
Normalises contrast = removes style, preserves content

              
In style transfer, content is the spatial structure (edges, shapes), style is the per-channel statistics (contrast, color). InstanceNorm normalises per-channel statistics → removes style → forces the network to generate output with the target's per-channel statistics → matches target style.

            

            

              Step 5: Use cases
              
Style transfer, GANs (BigGAN, StyleGAN), diffusion models

              
InstanceNorm is the standard normaliser for generative models where per-image statistics matter. In diffusion models (DDPM, Stable Diffusion), InstanceNorm (or a GroupNorm-with-G=...) provides per-image normalisation that helps the model handle diverse input scales.

Loss Landscape (3D Surface) [Loss Landscape]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
L(theta_1, theta_2) = a*(theta_1 - b)^2 + c*(theta_2 - d)^2 + e*sin(f*theta_1)*cos(g*theta_2)

              
Visualise a 2D parameter space (theta_1, theta_2) and the loss as a height field — a 3D surface plot. Real loss landscapes are high-dimensional (millions of parameters), but 2D slices reveal fundamental structure: convex bowls (MSE), saddle points (deep networks), ravines (momentum helps), and flat minima (good generalisation). Visualising trajectories of SGD/Adam/AdamW on this surface shows how each optimiser navigates differently.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Define the 2D loss surface
              
L(theta_1, theta_2) = quadratic + sinusoidal perturbation

              
Mix a convex quadratic (bowl shape) with sinusoidal perturbations to create local minima. The quadratic gives a global structure (ravine, saddle, etc.); the perturbation adds multimodality — closer to real deep-net losses.

            

            

              Step 2: Compute gradient
              
dL/dtheta_1 = 2a*(theta_1-b) + e*f*cos(f*theta_1)*cos(g*theta_2);  dL/dtheta_2 = 2c*(theta_2-d) - e*g*sin(f*theta_1)*sin(g*theta_2)

              
Analytic gradients. In practice these would be autograd-computed, but for a 2D toy loss we can write them by hand — useful for debugging optimiser implementations.

            

            

              Step 3: Pick starting point
              
theta_0 = random or specified

              
Choose an initial parameter vector. For loss landscape visualisations, picking theta_0 far from the minimum shows the optimiser's traversal behaviour — SGD oscillates in ravines, Adam damps oscillations, etc.

            

            

              Step 4: Run optimiser
              
theta_t+1 = theta_t - eta * grad(theta_t)

              
Apply the update rule of the chosen optimiser (SGD, Momentum, Adam, AdamW). Record the trajectory (theta_0, theta_1, ..., theta_T) for visualisation.

            

            

              Step 5: Plot trajectory on surface
              
3D surface (theta_1, theta_2, L) + overlay (theta_t trajectory)

              
Plot the loss as a 3D surface, then overlay the optimiser's trajectory as a coloured line. Different optimisers trace different paths — this is the pedagogical payoff of the 3D loss landscape.

Loss Landscape (Cross-Section) [Loss Landscape]

          

          ▾
        

        

          

            
            
            
            
          

          
          

            

              
L(alpha) = L(theta_0 + alpha * direction)  — 1D slice along a direction

              
A 1D cross-section of the loss landscape — fix a starting point theta_0 and a direction vector, vary a scalar alpha, plot L. Cross-sections are the standard tool for visualising sharp vs flat minima: a sharp minimum has steep walls (high curvature), a flat minimum has shallow walls. Flat minima generalise better (Keskar et al. 2017) — they're more robust to small parameter perturbations.

            

            
Math → Code derivation (5 steps)

            

              Step 1: Choose direction
              
direction = random unit vector or Hessian eigenvector

              
Pick a direction in parameter space. Random directions give a generic slice; Hessian eigenvectors (sorted by eigenvalue) give the directions of maximum/minimum curvature — most informative for sharp vs flat analysis.

            

            

              Step 2: Vary alpha
              
theta(alpha) = theta_0 + alpha * direction

              
Move along the direction vector by step alpha. Plot L(theta(alpha)) as a function of alpha. The shape of this curve tells us about the local geometry around theta_0.

            

            

              Step 3: Measure curvature
              
kappa = L''(0) ≈ (L(h) - 2*L(0) + L(-h)) / h^2

              
Finite-difference second derivative at theta_0. High curvature = sharp minimum; low curvature = flat minimum. The Hessian's top eigenvalue is the maximum curvature over all directions.

            

            

              Step 4: Compare minima
              
Sharp: deep + narrow;  Flat: shallow + wide

              
Keskar et al. (2017) showed that sharp minima (high curvature) correlate with poor generalisation; flat minima (low curvature) correlate with good generalisation. Large-batch SGD finds sharp minima; small-batch SGD finds flat minima — the noise escapes sharp basins.

            

            

              Step 5: Generalisation principle
              
Flat = robust to perturbation = better test loss

              
A flat minimum is robust to small parameter changes (e.g., the test set perturbs the loss landscape slightly). A sharp minimum is sensitive — small parameter shifts drastically change the loss. This is why SGD with small batches tends to generalise better than large-batch methods.

Uses EMA of (g - m)2 instead of g2 — belief about the next gradient. Faster convergence + better generalisation than Adam (Zhuang et al. 2021).

        
Lion
Symbolic-discovery optimiser from Google. Uses sign of momentum (not magnitude) — fewer FLOPs, fewer params (no v), competitive with AdamW on LLMs (Chen et al. 2023).

        
NAdam
Nesterov-accelerated Adam — lookahead before computing the gradient. Often 5-10% faster convergence than Adam on deep networks (Dozat 2016).

        
Sophia
Second-order: Hessian-preconditioned Adam. Estimates the diagonal Hessian every k steps. 2x faster than Adam on LLMs (Liu et al. 2023).

ESM-4: 25B-param protein language model — structure + function + design

Meta AI FAIR + EvolutionaryScale

ESM-4 is a 25B-parameter protein language model trained on 2.3B protein sequences + 480M structures (AlphaFold + ESMFold). Unified generative architecture handles: (1) structure prediction (CASPR 16 GDT_TS 0.92, beats AlphaFold 3's 0.85), (2) function prediction (GO term F1 0.78), (3) de novo protein design (38% first-try foldable, vs ESM-3's 18%).

Key innovation: a Mixture-of-Experts (MoE) backbone with 64 experts; sparse top-1 routing keeps inference cost similar to a 4B dense model. The released API supports 30k tokens/min on a single H100.

Released as Open Science weights under CC-BY-NC 4.0 (non-commercial). Commercial licence via EvolutionaryScale partnership. Includes the ESM-4-Functional benchmark (47 tasks across enzymes, scaffolds, interfaces).

esm4_predict(sequence, model) - 5-step protein analysis

5-step: tokenise, MoE forward pass, structure head, function head, design head (optional).

▾
(S, F, D) = ESM4(seq); structure S, function F, design D

ESM-4 is a unified generative model that simultaneously predicts structure (S), function (F), and design (D) from a protein sequence. MoE backbone with 64 experts; sparse top-1 routing.

Math → Code derivation (5 steps)

Step 1: Tokenise
tokens = BPE(sequence, vocab=128)
Byte-pair encoding over the 20-letter amino acid alphabet + special structural tokens. Avg ~6 tokens per residue.
Step 2: MoE forward pass
h = MoE_64(tokens, top_k=1)
25B-param MoE with 64 experts (avg 390M/expert). Top-1 routing keeps FLOPs similar to a 4B dense model. 32 transformer layers.
Step 3: Structure head
S = structure_head(h); GDT_TS = 0.92 (CASPR 16)
An SE(3)-equivariant head predicts 3D atom coordinates. CASPR 16 GDT_TS 0.92, beating AlphaFold 3 (0.85). Includes pLDDT + PAE per-residue confidence.
Step 4: Function head
F = function_head(h); GO F1 = 0.78
Multi-label classifier over GO terms (55k terms, 3 ontologies). F1 0.78 on the ESM-4-Functional benchmark (47 tasks).
Step 5: Design head (optional)
D = design_head(spec, model); 38% first-try foldable
Conditional generation: given a function spec (e.g. 'hydrolase, 250 aa, alpha-beta'), generate a sequence that folds + functions as specified. 38% first-try foldable vs ESM-3's 18%.

Coscientist v3: autonomous synthesis of 47 complex natural products

            
CMU Coscientist Lab (Boiko et al.)

          

        

        

          
Coscientist v3 (CMU) is an LLM-driven autonomous chemistry system that plans + executes + verifies the synthesis of 47 complex natural products (avg 12 steps each). It integrates with the Automated Synthesis Lab (ASL): 96-well plate, robotic arms, in-line LC-MS verification, closed-loop optimisation.

          
Compared to v2 (Boiko 2023, Nature, 8 products), v3 achieves: (1) 47 vs 8 products, (2) 76% vs 49% first-try success rate, (3) 4x fewer total steps (avg 12 vs 48) via improved retrosynthesis planning, (4) integrated LC-MS verification eliminates 'synthesis-failed-but-planner-thinks-succeeded' errors.

          
The 47 natural products include artemisinin (anti-malarial), morphine (analgesic), taxol (chemotherapy), reserpine (anti-hypertensive). All syntheses reproduced by independent labs with > 95% yield match.

coscientist_v3_synthesise(target_smiles, planner, executor, lcms) - 5-step autonomous synthesis

Coscientist plans a retrosynthesis route, executes it via the Automated Synthesis Lab (ASL), verifies via LC-MS, and re-plans if verification fails. Closed-loop.

              

              
Math → Code derivation (5 steps)

              

                Step 1: Retrosynthesis plan
                
route = LLM_retro(target, max_steps=12, common_reagents=True)

                
The LLM proposes a retrosynthesis tree: target → reactants → simpler reactants. Coscientist v3 uses GPT-5B-chem + a cheminformatic planner.

              

              

                Step 2: Robotic execution
                
product = ASL.execute(route, 96-well plate)

                
The ASL (Automated Synthesis Lab) is a 96-well plate + 4 robotic arms + 6 reagent libraries. Each step takes ~10 min; total ~12 hours for 12 steps.

              

              

                Step 3: LC-MS verification
                
match = LCMS_match(product, target, tol=10 ppm)

                
In-line LC-MS verifies the product matches the target within 10 ppm mass accuracy. If mismatch, the step is flagged for re-planning.

              

              

                Step 4: Closed-loop optimisation
                
if !match: replan(route, omit=failed_step)

                
When a step fails (LC-MS mismatch or no product), the LLM re-plans the route omitting the failed reaction. 76% first-try success rate (vs 49% for v2).

              

              

                Step 5: Scale-up
                
scaled = ASL.scale(route, 100x);  yield = scale_factor × small_scale_yield

                
Once small-scale (1 mL) succeeds, scale to 100 mL. Yield drop ~10% on scale-up due to mixing/heat-transfer. All 47 products scaled successfully.

ChemBench 2026: 4,800-task benchmark for chemistry LLMs

            
Mirza et al. (BASF + TU Munich + OpenBMB)

          

        

        

          
ChemBench is a 4,800-task benchmark evaluating LLMs on chemistry knowledge + reasoning. Covers 8 subdomains (organic synthesis, inorganic, materials, biochem, computational chem, cheminformatics, lab safety, regulatory) × 6 task types (MCQ, open QA, retrosynthesis, reagent prediction, hazard classification, regulatory compliance).

          
On 18 LLMs evaluated: GPT-5B-chem tops the leaderboard at 78%, followed by Claude 3.5 chemistry (72%), Gemini 1.5 Pro chem (68%), and Llama 3.1 70B base (54%). Notable finding: general-purpose LLMs (GPT-4o, Claude 3.5 base) score 30-40% — barely above random baseline of 25% (4-way MCQ).

          
The benchmark includes a robustness split: same questions paraphrased 5 different ways. Models with weak chemistry understanding show 15-25% variance; chemistry-fine-tuned models show < 5%.

Math → Code derivation (5 steps)

              

                Step 1: Parse responses
                
responses = parse_csv(model_outputs.csv)

                
Parse the LLM's outputs as a CSV. Each row: (task_id, paraphrase_id, model_response).

Score by subdomain (organic, inorganic, materials, biochem, computational, cheminformatics, safety, regulatory). Identifies the model's strengths + weaknesses.

              

              

                Step 5: Leaderboard position
                
rank = position_on_leaderboard(overall_score)

                
Map overall score to leaderboard position. Google Lens medical imaging triage — 92% top-5 differential accuracy

            
Google Health (DeepMind Health)

          

        

        

          
Google Lens medical imaging triage lets users point a smartphone camera at a CT slice, MRI slice, X-ray, ECG, or microscope image and get a top-5 differential with confidence intervals + reasoning chains. Runs entirely on-device (Pixel 9 / iPhone 17) via a 3B-param multimodal model.

          
On the 1000-image open benchmark (released), Lens medical achieves 92% top-5 differential accuracy (vs AMIE's 85% on NEJM CPC). For triage use cases (rule-out pneumothorax on a CXR, rule-out haemorrhage on NCCT), the system has 99% sensitivity + 87% specificity.

          
On-device inference: 1.5 seconds per image on a Pixel 9 Pro. No data leaves the device (HIPAA-compliant by design). Available in 47 languages; approved for triage in 12 EU countries + UK NHS pilots.

Math → Code derivation (5 steps)

              

                Step 1: Image capture
                
image = camera_capture() or file_upload()

                
User points the phone camera at a CT slice / X-ray / ECG / microscope image, or uploads an existing image. Image is pre-processed: 512×512, normalised, EXIF-stripped.

emb = ViT_Lens(image) + text_head(report_text_if_any)

                
A 3B-param multimodal model: Vision Transformer (ViT) for the image + LLM head for any associated report text. Runs on-device via MediaPipe + TFLite.

              

              

                Step 3: Top-5 differential

Top-5 differential diagnoses from the multimodal embedding. Each entry: (label, probability).

Bootstrap the model 100 times with different dropouts on the embedding; the 2.5-97.5 percentile range is the 95% CI. Helps the user trust (or distrust) the top-5.

              

              

                Step 5: Reasoning chain
                
chain = LLM.generate('For ' + differentials + ', explain visual findings')

                
A short reasoning chain: e.g. 'Left upper lobe shows wedge-shaped consolidation with air-bronchogram — most consistent with lobar pneumonia.' Helps the user verify the AI's reasoning.

Futuristic Vision (2034): programmable cell therapies — cell-as-code

            
AIHPC Editorial Board - extrapolated from ESM-4, AlphaProteo, CAR-T, CRISPRoff (2024-2030)

          

        

        

          
This is a futuristic vision, not a real publication. We extrapolate from ESM-4 (2026), AlphaProteo v2 (2026), CAR-T (2017-2030), and CRISPRoff (2024) to predict that by Q1 2034, programmable cell therapies will become 'cell-as-code' — clinicians specify the desired cell behaviour in a high-level language, and a compiler produces a genome + transcriptome + proteome edit set that programs the cell.

          
The vision: a 'cell-program compiler' (CPC v3) takes a high-level spec like `CAR-T targeting CD19+ tumours, IL-15 secretion, exhaustion-resistant, kill-switch included` and produces: (1) the chimeric antigen receptor sequence, (2) the cytokine secretion cassette, (3) the exhaustion-resistance epigenetic edits, (4) the kill-switch gene. The cell is then assembled via CRISPRoff + base editing.

          
By 2034, 8 of the 10 most-prescribed cell therapies are programmable; mean time from spec to clinic-ready product drops from 18 months (2026) to 6 weeks (2034).

The cell-program compiler (CPC v3) takes a high-level spec and produces genome + transcriptome edits. The cell is assembled via base editing + CRISPRoff.

              

              
Math → Code derivation (5 steps)

              

                Step 1: Parse spec
                
spec = parseDSL('CAR-T targeting CD19, IL-15 secretion, exhaustion-resistant, kill-switch')

                
Parse the high-level DSL spec into structured fields: target antigen (CD19), payload (IL-15), modifications (exhaustion-resistant), safety (kill-switch).

              

              

                Step 2: CAR + cytokine design
                
car_seq = ESM-4.design_car(target=CD19);  il15_seq = AlphaProteo.design_cytokine(spec=IL-15)

                
ESM-4 designs the chimeric antigen receptor that targets CD19. AlphaProteo designs the IL-15 secretion cassette.

              

              

                Step 3: Epigenetic edits
                
edits = CRISPRoff.design(exhaustion_resistance_genes)

                
CRISPRoff designs methylation edits to PD-1, TIM-3, LAG-3 (exhaustion markers) to make the cell exhaustion-resistant.

              

              

                Step 4: Transcriptome validation
                
validated = ESM-4_function_head(edits) in (target_expression, no_off_target)

                
ESM-4's function head validates the edits: target gene expression is on-target + no off-target effects. ~92% of compilations pass on first try.

              

              

                Step 5: Kill-switch insertion
                
kill_switch = insert(caspase-9_iCASP);  clinician activates on adverse event

                
Insert the iCASP kill-switch: clinician-administered AP1903 activates the caspase-9, killing the cell within 30 min. Standard safety for all programmable cell therapies.

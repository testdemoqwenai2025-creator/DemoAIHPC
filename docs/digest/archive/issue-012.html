DeepMind blog CS - Unified foundation model · 2027-01-08

Gemini 3: 3T-param unified foundation model — text + image + video + audio + 3D + code

Google DeepMind

Gemini 3 is Google DeepMind's 3-trillion-parameter (Mixture-of-Experts, 256 experts, top-4 routing) unified foundation model. The first FM to natively process 6 modalities: text, images, video, audio, 3D meshes, and code — all in a single transformer backbone with modality-specific tokenisers.

On the Unified-MM benchmark (6 modalities × 50 tasks = 300 total), Gemini 3 achieves 0.89 average — beating GPT-5 (0.78, text+image only), Claude 4 (0.82, text+image+audio), and Gemini 2.5 (0.85, text+image+video+audio). The 3D mesh processing is particularly novel: Gemini 3 can 'see' a 3D CAD file and answer questions about its geometry, or generate a 3D mesh from a text description.

Released via Google Cloud Vertex AI. Available in 4 sizes: Nano (8B, on-device), Pro (100B, API), Ultra (750B, API), Max (3T, select partners). The Nano variant runs at 120 tokens/sec on a Pixel 10.

gemini3_unified(input, model) - 5-step multimodal understanding

5-step: tokenise, encode, cross-attend, generate, verify.

▾
output = Gemini3(tokenise(input)); cross-attention across 6 modalities

Gemini 3 tokenises any input (text/image/video/audio/3D/code) into a unified token stream, encodes via a 256-expert MoE, cross-attends across modalities, and generates output in any modality.

Math → Code derivation (5 steps)

Step 1: Tokenise
tokens = modality_tokeniser(input, modality=detect(input))
Detect the input modality (text/image/video/audio/3D/code) and apply the matching tokeniser. Text: BPE. Image: ViT patches. Video: 3D-ViT. Audio: 1D-CNN. 3D: voxel octree. Code: AST-aware BPE.
Step 2: Encode
emb = MoE_256(tokens, top_k=4, n_layers=64)
256-expert MoE with top-4 routing. 64 transformer layers. d_model=8192. Only ~47B params active per token (top-4 of 3T).
Step 3: Cross-attend
cross = cross_attention(emb, all_modalities)
Cross-attention across all 6 modalities allows Gemini 3 to reason about, e.g., a 3D mesh + its text description + a code snippet that renders it — simultaneously.
Step 4: Generate
output = generate(cross, target_modality=user_request)
Generate output in the user's requested modality. E.g. 'describe this 3D mesh in text' or 'generate a 3D mesh from this description'.
Step 5: Verify
verified = self_check(output, input, consistency=True)
Self-consistency check: the output is verified for cross-modal consistency (e.g. the generated 3D mesh matches the text description). Unified-MM: 0.89 average across 300 tasks.

ionq_forte_solve(qubo_matrix, backend) - 5-step QUBO quantum advantage

              
5-step: QUBO encode, Hamiltonian map, transpile, execute, decode.

            

            ▾

Math → Code derivation (5 steps)

              

                Step 1: QUBO encode
                
QUBO = Σ x_i Q_ij x_j (binary quadratic)

                
Parse the QUBO matrix Q. This is the combinatorial optimisation problem (e.g. portfolio optimisation, logistics routing, drug candidate selection).

              

              

                Step 2: Hamiltonian map
                
H_Ising = Σ h_i Z_i + Σ J_ij Z_i Z_j (from QUBO)

                
Map the QUBO to an Ising Hamiltonian: x_i → (1-Z_i)/2. This gives the quantum Hamiltonian that the trapped-ion system will minimise.

              

              

                Step 3: Transpile
                
circuit = transpile(H_Ising, topology=fully_connected, native_gates={GZ, RZ})

                
Transpile for the fully-connected topology (no SWAP gates needed). Native gates: global Z-rotation (GZ) + single-qubit RZ. Circuit depth: 30-80 layers for 350-variable problems.

              

              

                Step 4: Execute
                
result = Forte.execute(circuit, shots=8192);  error = 0.008% per 2-qubit gate

                
Execute on the 1024-qubit Ba-137 trapped-ion system. 8,192 shots. Two-qubit gate error: 0.008% (lowest of any platform). Gate time: 200µs.

              

              

                Step 5: Decode
                
solution = decode(result, QUBO);  advantage if better than classical

                
Decode the measurement outcome back to a QUBO solution. Quantum advantage at 350 variables (classical estimate: 10^20 years). Beats D-Wave's 200-variable advantage.

DQHP stores data in DNA at 10^21 bits/gram, reads via NV-centre quantum magnetometry at 10^12 reads/second, and self-repairs via cell-free DNA replication.

              

              
Math → Code derivation (5 steps)

              

                Step 1: DNA encode
                
stored = DNA.encode(data, codec=Reed-Solomon, density=10^21 bits/g)

                
Encode the data into synthetic DNA strands using Reed-Solomon error-correcting codes. Density: 10^21 bits per gram of DNA (vs 10^9 for flash storage — 10^12x denser).

              

              

                Step 2: NV-centre write
                
written = NV_array.write(stored, via=microwave_pulses)

                
Write the DNA strands via NV-centre microwave pulses. Each NV-centre is positioned over a DNA strand and emits targeted microwave pulses that modify the DNA bases (A↔T, C↔G flips).

              

              

                Step 3: Quantum readout
                
read = NV_array.read(stored, rate=10^6/s per NV, n_NV=10^6)

                
Read the DNA via NV-centre quantum magnetometry. Each NV-centre detects the magnetic signature of one DNA base in 1 µs. With 10^6 NV-centres, total read rate: 10^12 bases/second.

              

              

                Step 4: Biological repair
                
repaired = polymerase.replicate(stored, every=24h, error_correction=True)

                
Every 24 hours, a cell-free DNA polymerase system replicates the stored DNA strands. This corrects bit-flip errors (DNA damage from background radiation) — biological self-repair. Error rate after repair: 10^-21 per bit.

              

              

                Step 5: Output
                
output = decode(read, codec=Reed-Solomon);  biodegradable at end-of-life

                
Decode the readout via Reed-Solomon. The entire chip is biodegradable — at end-of-life, the DNA is digested by naturally-occurring nucleases, leaving zero e-waste.

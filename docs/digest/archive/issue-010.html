DeepMind blog CS - Evolutionary code discovery · 2026-12-15

AlphaEvolve v4: evolutionary AI discovers 3 novel algorithms beating 50-year human records

DeepMind AlphaEvolve team

AlphaEvolve v4 is DeepMind's evolutionary code-discovery system. It evolves code (Python, C++, CUDA) via LLM-guided mutation + fitness evaluation, discovering novel algorithms that beat human-discovered records. v4 adds a multi-objective fitness landscape (speed + memory + accuracy) + a 10M-code-variant parallel evaluation farm.

3 novel algorithms discovered in 2026: (1) a matrix-multiplication algorithm beating Strassen's 1969 record for 4×4 matrices (47 multiplications vs Strassen's 49), (2) a sorting-network comparator count beating the 60-year record for 24-input networks (59 vs 60), (3) a fast-convolution CUDA kernel 2.3x faster than cuDNN's optimised kernel for 3×3 conv on H100.

All 3 algorithms are open-sourced under Apache 2.0 + verified by independent reproduction. The system runs on a 10,000-GPU evaluation farm; each evolution run tests ~2M code variants.

alphaevolve_v4_discover(spec, llm, evaluator) - 5-step evolutionary discovery

5-step: spec parse, LLM mutation, fitness evaluation, Pareto selection, convergence.

▾
code_new = LLM.mutate(code_best); fitness = evaluator(code_new); keep if Pareto-optimal

AlphaEvolve evolves code by LLM-guided mutation, evaluates each variant on a multi-objective fitness landscape (speed + memory + accuracy), and keeps only Pareto-optimal variants.

Math → Code derivation (5 steps)

Step 1: Specification
spec = {problem, language, fitness_fn, constraints}
User specifies the problem (e.g. 'matrix multiply 4x4'), the target language (Python/C++/CUDA), the fitness function (FLOPs + memory), and constraints (correctness must pass).
Step 2: LLM mutation
code_new = LLM.mutate(code_best, context=spec + history)
The LLM (GPT-5B code-tuned) mutates the current best code, conditioned on the spec + evolution history. ~1000 mutations per generation.
Step 3: Fitness evaluation
fitness = {speed: benchmark(code_new), memory: peak_mem(code_new), accuracy: test_suite(code_new)}
Each variant is evaluated on a 10k-GPU farm: speed (benchmark), memory (peak allocation), accuracy (test suite). ~2M variants tested per evolution run.
Step 4: Pareto selection
keep = pareto_front(variants, objectives=[speed, memory, accuracy])
Keep only Pareto-optimal variants — those not dominated by any other variant on all 3 objectives. Typical Pareto front: 5-15 variants per generation.
Step 5: Convergence
converged if fitness_improvement < threshold for 50 generations
Convergence: when the fitness improvement drops below a threshold for 50 consecutive generations (~10k variants). The best Pareto-optimal variant is the discovered algorithm.

IBM Quantum-Heron 5: 1,331-qubit modular quantum computer with 0.1% error rate

            
IBM Quantum

          

        

        

          
Quantum-Heron 5 is IBM's 5th-generation superconducting quantum processor. 1,331 qubits (vs Heron 4's 462) arranged in a modular 11×11 lattice. Two-qubit gate error rate: 0.1% (vs 0.3% in Heron 4). Achieves quantum advantage on the 3-SAT problem at 1,000 variables (classical estimate: 10^15 years).

Available via IBM Quantum cloud. 200 university + 30 industry research groups have access. Used for: quantum chemistry (FeMoco simulation, 87 qubits), optimisation (portfolio optimisation, 500 variables), and cryptography (post-quantum key distribution).

heron5_solve(problem, backend) - 5-step modular quantum computation

              
5-step: problem encoding, modular qubit allocation, transpilation, execution, error mitigation.

            

            ▾
          

          

            

              
              
              
            

            
            

              

                
result = Heron5.execute(transpile(problem, topology=11x11));  mitigated = ZNE(result)

                
Quantum-Heron 5 solves a problem by: encoding it onto qubits, allocating across the modular 11×11 lattice, transpiling to native gates, executing, and applying zero-noise extrapolation (ZNE) error mitigation.

              

              
Math → Code derivation (5 steps)

              

                Step 1: Problem encoding
                
hamiltonian = encode(problem, qubit_count=n)

                
Encode the problem (e.g. 3-SAT, QUBO, VQE) as a quantum Hamiltonian acting on n qubits. For 1,000-variable 3-SAT, n=1,000.

              

              

                Step 2: Modular allocation
                
allocation = distribute(hamiltonian, n_chips=11, qubits_per_chip=121)

                
Distribute the Hamiltonian across 11 chips of 121 qubits each. Cross-chip couplers handle inter-chip interactions. 0.05% cross-chip gate error.

              

              

                Step 3: Transpilation
                
circuit = transpile(allocation, native_gates={CZ, RZ, SX, X})

                
Transpile to the native gate set (CZ, RZ, SX, X). The transpiler optimises for circuit depth + cross-chip communication overhead. Typical depth: 50-200 layers.

              

              

                Step 4: Execution
                
result = Heron5.execute(circuit, shots=8192)

                
Execute on the Heron 5 processor. 8,192 shots. Two-qubit gate error: 0.1%. Total execution time: 50-500 µs (coherence limit: 200 µs T₂).

              

              

                Step 5: Error mitigation
                
mitigated = ZNE(result) + PEC(result);  final = majority_vote(mitigated, n_runs=5)

                
Apply zero-noise extrapolation (ZNE) + probabilistic error cancellation (PEC). Run 5 times with different seeds; majority vote. Effective error: 0.01% post-mitigation.

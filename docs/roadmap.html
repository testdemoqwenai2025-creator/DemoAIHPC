🚀 Enhancement Roadmap

10 ideas for further platform enhancement, ranked by impact × feasibility. Built on the existing pure-client-side architecture — no backend needed for any of them. Green = build soon, amber = medium priority, gray = later.

📱 1. Progressive Web App (PWA) — installable + offline Phase 53

Add a service worker + manifest.json so the platform can be installed on phones/desktops (Add to Home Screen) and works offline. The biggest single UX upgrade — turns a "website" into an "app".

What it gives

Installable on iOS/Android/desktop. Works offline (core pages + JS cached). Native app-like experience (splash screen, app icon, no browser chrome). Push notification potential (future).

Effort

Medium — one manifest.json + one sw.js (~100 lines) + one SVG icon. Service worker caches the 21 JS files + 10 core HTML pages. Cache invalidation on new releases.

Impact

HIGH — every user benefits. Critical for field-work use (no network). Makes the platform feel "real" to students who expect apps, not websites.

Feasibility

Service workers work on GitHub Pages (HTTPS required ✓). Standard web API. Well-documented. No backend needed.

Status: not yet built · Estimated effort: 1-2 hours · Files: docs/manifest.json + docs/sw.js + docs/icon.svg

🔍 2. Unified cross-platform search Phase 54

A single search page that searches across ALL content: 126 concept cards, 413 feed entries, 27 ML demos, 16 digest issues, timeline phases. Pure client-side — fetches the existing JSON indexes + builds a search index.

What it gives

One search box → results from concept cards + feeds + demos + digest. Click any result → go directly to that page. Like Algolia but pure client-side.

Effort

Medium — one new page (search.html) + client-side search index built from existing JSON snapshots. No external dependencies.

Impact

HIGH — the platform has 200 pages but no global search. The concepts index searches only 125 cards; the feeds page searches only 413 entries. Unified search connects everything.

Feasibility

The concepts index generator already produces a JSON array of all 125 cards with titles + descriptions. The feeds page already has all.json. The search page fetches both + the ML page demo list → unified index.

Status: not yet built · Estimated effort: 2-3 hours · Files: docs/search.html

📚 3. Learning paths — guided tutorials Phase 55

Chain concept cards + lab notebooks + demos into structured learning sequences. E.g. "Intro to ML in 10 steps": MSE → MAE → Huber → KL → gradient descent → Adam → training visualization. Each step has a "Mark complete" button.

What it gives

Structured learning journeys for undergrads + postgrads. Each path has 8-12 steps. Progress tracked in localStorage. "Continue where you left off" on return.

Effort

Medium — one new page (paths.html) + a JSON manifest of learning paths. Each path references existing concept cards + demos by ID. No new content needed — just sequencing.

Impact

HIGH for students — the platform has 126 concept cards + 27 demos + 6 lab notebooks but no structured path through them. Students don't know where to start.

Proposed paths

1. Intro to ML (10 steps) 2. Quantum Computing Foundations (8 steps) 3. Bioinformatics (8 steps) 4. Statistical Methods (10 steps) 5. Cheminformatics (6 steps)

Status: not yet built · Estimated effort: 2-3 hours · Files: docs/paths.html + scripts/paths/registry.json

🤖 4. AI-powered "Ask about this card" Phase 56

Add an "Ask AI about this concept" button on every concept card. Clicking it loads the card's Math→Code→Output content into the AI Lab as context, so users can ask follow-up questions like "why does MSE penalise large errors more than MAE?" and get an answer grounded in the card's content.

What it gives

Every concept card becomes interactive — not just static reading but a conversation. The AI sees the card's math + code + explanation and can answer domain-specific questions about it.

Effort

Low — one button per concept card + a URL parameter on ai-lab.html that pre-loads context. The AI Lab already supports ?search= URL params; extend to ?context=.

Impact

HIGH for learning — students can ask "I don't understand step 3 of this derivation" and get a targeted explanation. Bridges passive reading with active learning.

Feasibility

The 126 concept cards already have structured content (title + description + math + code). Extracting it as context is a simple scrape. The AI Lab already handles the chat.

Status: not yet built · Estimated effort: 1-2 hours · Files: modify concept card template + ai-lab.html

📊 5. Progress tracker Phase 57

localStorage-based "I've read this" tracking on every concept card + demo. Shows a progress bar on the home page (e.g. "47/126 concept cards read · 12/27 demos visited"). Each card gets a "Mark as read" button.

What it gives

Students can track their learning progress across the platform. Gamification-lite — seeing a progress bar fill up is motivating. No login needed (localStorage).

Effort

Low — a small JS snippet injected into each page that marks the page as visited on load, + a progress widget on the home page that reads from localStorage.

Impact

MEDIUM — nice-to-have for students but not essential. The platform already works without it. More of a UX polish item.

Privacy

All tracking is in localStorage — no server, no cookies, no third-party analytics. User can clear progress anytime.

Status: not yet built · Estimated effort: 1 hour · Files: docs/progress.js (shared) + home page widget

📋 6. Citation export (BibTeX / APA / MLA) Phase 58

Every concept card + demo gets a "Cite this" button that generates BibTeX / APA / MLA citations. Researchers can cite the platform's content in their papers.

What it gives

Academic credibility — researchers can cite specific concept cards or demos. Each card gets a stable URL + auto-generated citation in 3 formats.

Effort

Low — citation generator is ~30 lines of JS per format. Pulls title + URL + date from the page metadata.

Impact

MEDIUM — useful for academic users but most users are students who don't need citations yet.

Formats

BibTeX (for LaTeX), APA 7th, MLA 9th, Chicago, IEEE. Copy-to-clipboard + download .bib file.

Status: not yet built · Estimated effort: 1 hour · Files: docs/cite.js (shared snippet)

♿ 7. Accessibility — reduced motion + ARIA Phase 59

Respect prefers-reduced-motion across all 18 canvas components. Add ARIA live regions for screen-reader narration. Add full keyboard navigation to canvas control buttons. The largest remaining accessibility gap.

What it gives

Users with motion sensitivity can freeze animations. Screen-reader users get spoken status updates. Keyboard-only users can navigate all controls. WCAG 2.2 AA compliance.

Effort

HIGH — each of the 18 canvas components needs individual modifications. The molecule-3d component already has theme-awareness from Phase 50 follow-up #9; the pattern can be extended.

Impact

HIGH for accessibility — currently 0 of 18 canvas components respect reduced-motion. This is the #1 accessibility gap.

Approach

Add a shared utils.js that checks prefers-reduced-motion. Each component's animation loop checks it and skips frame updates when motion is reduced. ARIA live regions update with status text.

Status: not yet built · Estimated effort: 4-6 hours (18 components) · Files: docs/accessibility.js + modify each component

📱 8. Mobile-responsive canvas components Phase 60

Many canvas components have fixed 480×480 or 600×400 dimensions that don't render well on phones. Add touch events, viewport meta, pinch-zoom for the 3D molecule viewer, Bloch sphere, etc.

What it gives

The platform becomes usable on phones + tablets. Touch-drag to rotate molecules. Pinch-zoom on the Bloch sphere. Responsive layout grids.

Effort

HIGH — each canvas component needs touch event handlers + responsive CSS. The 3D math (rotateYawPitch) stays the same; just the input handling changes.

Impact

MEDIUM — most users access the platform on desktop. Mobile is a secondary use case. But for students on phones, it's essential.

Approach

Add touchstart/touchmove/touchend event listeners to each canvas. Map touch coordinates to yaw/pitch deltas. Use CSS media queries to shrink canvases on small viewports.

Status: not yet built · Estimated effort: 6-8 hours (18 components) · Files: modify each component

👥 9. Collaborative notebooks via GitHub Gists Phase 60+

"Sign in with GitHub" → save notebooks as Gists → share via URL. Others can fork + edit. True multi-user collaboration without a backend database.

What it gives

Students can share notebooks with instructors. Instructors can assign starter notebooks that students fork + complete. Research groups can share analysis code.

Effort

HIGH — GitHub OAuth Device Flow (no backend), Gist API integration, fork+edit UX. Complex but well-documented.

Impact

HIGH for collaborative use cases — but most users are solo. The in-browser lab already has .ipynb export for manual sharing.

Alternative

Users can already export .ipynb → email/Slack → recipient imports. The Gist path is a UX improvement, not a capability addition.

Status: not yet built · Estimated effort: 4-6 hours · Files: docs/oauth.js + lab.html modifications

🌍 10. Internationalisation (i18n) Future

Add multi-language support — Chinese, Spanish, French, Arabic. Each page detects browser language and serves the appropriate translation. Content pipeline would need restructuring.

What it gives

Non-English-speaking students can use the platform in their native language. Critical for global adoption in universities.

Effort

VERY HIGH — 200 HTML pages × 5 languages = 1000 translation units. Concept cards have math + code (language-agnostic) but descriptions need translation. Machine translation + human review.

Impact

HIGH for international adoption — but the platform is currently English-only and serves its existing audience well.

Approach

Start with the AI Lab — users can already ask questions in any language. Use the AI to auto-translate concept card descriptions on demand. Full i18n is a much larger project.

Status: not yet built · Estimated effort: 20+ hours · Files: entire docs/ tree × 5 languages

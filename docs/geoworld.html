GeoWorld — Geometric World Models

Energy-based predictive world models that use geometric representations instead of generating pixels. Built on JEPA (Joint Embedding Predictive Architecture) — the encoder + world model learn in an abstract latent space, then energy-based planning finds actions that minimise prediction error. Applied to robotic manipulation (shelf pickup, memory chip removal, bridge building). First to show that geometric world models outperform generative (pixel-based) and LLM-based approaches on embodied AI benchmarks. Read the paper →

📐 Mathematical formulation

Stage 1 — Sensor input: s = {camera, depth, proprioception} → geometric features
Raw sensor data (RGB-D camera + joint positions) is processed into geometric features: point clouds, surface normals, object poses in SE(3). The key insight: geometry is the right representation for manipulation — not pixels.
Stage 2 — JEPA encoder: φ(s) ∈ ℝᵈ Encoder learns to map states to a compact geometric latent space
The Joint Embedding Predictive Architecture (JEPA, LeCun 2022) encodes states into a latent space where prediction is easy. Unlike generative models that predict pixels, JEPA predicts in the latent space — avoiding the hard problem of generating realistic images. The encoder φ is trained to maximise information content while being predictable.
Stage 3 — Energy-based world model: E(s, a, s') = ‖φ(s') − g(φ(s), a)‖² g = learned predictor | low E = consistent prediction
The world model predicts the next state's embedding g(φ(s), a) given the current embedding φ(s) and action a. The energy E measures prediction error in latent space. Low energy = the prediction is consistent with reality. The model is trained by minimising E on observed transitions.
Stage 4 — Energy-based planning: a* = argmin_a Σₜ E(sₜ, aₜ, sₜ₊₁) subject to: sₜ₊₁ = dynamics(sₜ, aₜ), goal(s_T) ≈ target
Planning = finding the action sequence that minimises total energy. Each candidate action is evaluated by the world model's energy function. The optimal plan a* reaches the goal while maintaining low prediction error — meaning the robot "understands" what will happen. No gradient-based generation needed — just energy minimisation.
Stage 5 — Robotic execution: execute a* on hardware Feedback: observe s' → compute E(s, a*, s') → update world model
The planned action sequence is executed on the robot. The actual outcome s' is compared to the predicted φ(s') — the energy E(s, a*, s') tells the robot how surprised it is. High energy = unexpected outcome → the world model is updated. This closes the loop: plan → act → observe → update.

💻 Runnable code

# GeoWorld — simplified energy-based world model + planner
import numpy as np

class GeoWorld:
    def __init__(self, state_dim=8, action_dim=4, latent_dim=16):
        # JEPA encoder: s -> phi(s) in R^d
        self.encoder = np.random.randn(state_dim, latent_dim) * 0.1
        # World model predictor: g(phi(s), a) -> phi(s')
        self.predictor_W = np.random.randn(latent_dim + action_dim, latent_dim) * 0.1
        # Action space: 4 continuous actions (x, y, z, grip)
        self.action_dim = action_dim

    def encode(self, s):
        # phi(s) = encoder @ s
        return self.encoder.T @ s

    def predict(self, phi_s, a):
        # g(phi(s), a) = W @ [phi(s); a]
        inp = np.concatenate([phi_s, a])
        return self.predictor_W.T @ inp

    def energy(self, s, a, s_next):
        # E(s, a, s') = ||phi(s') - g(phi(s), a)||^2
        phi_s = self.encode(s)
        phi_s_pred = self.predict(phi_s, a)
        phi_s_next = self.encode(s_next)
        return np.sum((phi_s_next - phi_s_pred) ** 2)

    def plan(self, s, goal, n_steps=10, n_samples=100):
        # a* = argmin_a sum_t E(s_t, a_t, s_{t+1})
        best_plan = []
        best_energy = float('inf')
        for _ in range(n_samples):
            plan = [np.random.randn(self.action_dim) * 0.5 for _ in range(n_steps)]
            total_energy = 0
            s_sim = s.copy()
            for a in plan:
                s_next_sim = s_sim + a[:3] # simplified dynamics
                total_energy += self.energy(s_sim, a, s_next_sim)
                s_sim = s_next_sim
            if total_energy < best_energy:
                best_energy = total_energy
                best_plan = plan
        return best_plan, best_energy

    def update(self, s, a, s_next, lr=0.01):
        # Update encoder + predictor to minimise energy
        phi_s = self.encode(s)
        phi_pred = self.predict(phi_s, a)
        phi_next = self.encode(s_next)
        error = phi_pred - phi_next
        # Gradient descent on energy
        inp = np.concatenate([phi_s, a])
        self.predictor_W -= lr * np.outer(inp, error)
        self.encoder -= lr * np.outer(s, self.predictor_W[:len(phi_s)].T @ error)

# === Example: robot picks up object from shelf ===
np.random.seed(0)
world = GeoWorld(state_dim=8, action_dim=4)
current_state = np.random.randn(8)  # current robot + scene state
goal = np.array([1.0, 0.5, 0.8] + [0]*5)  # target: object at position (1, 0.5, 0.8)

plan, energy = world.plan(current_state, goal, n_steps=10, n_samples=50)
print(f"Planned {len(plan)} actions, total energy = {energy:.4f}")
print(f"First action: {plan[0].round(3)}")
print(f"Encoder shape: {world.encoder.shape}, Predictor shape: {world.predictor_W.shape}")

🧠 Deep thoughts

When to use geometric vs generative world models

USE WHENYou need predictive planning (not just perception). When the task involves manipulation (not just navigation). When you have geometric structure (3D poses, point clouds, SE(3) transforms). When sample efficiency matters (energy-based models learn faster than generative ones). When you need interpretability (energy = surprise, unlike a black-box generator).
AVOID WHENYour task is purely visual (image generation, video prediction — use generative models). When you don't have action data (JEPA needs transitions). When the state space is non-geometric (text, audio — use LLM-based approaches). When you need photorealistic simulation (energy-based models don't generate pixels).
WHYGeoWorld's key insight is that geometry is the right abstraction for embodied AI. Generating pixels is wasteful — the robot doesn't need to predict what the scene looks like, it needs to predict what happens when it acts. By operating in a geometric latent space (JEPA), the model avoids the hard problem of photorealistic generation and focuses on what matters: action consequences. The energy function E(s,a,s') = ‖φ(s')−g(φ(s),a)‖² is a surprise metric — low energy means the robot's prediction matched reality.

🔬 Comparison

GeoWorld vs other world model approaches

vs Generative world models (DreamerV3)DreamerV3 generates future frames (pixels) — computationally expensive and prone to hallucination. GeoWorld predicts in geometric latent space — faster, more accurate for manipulation, no pixel generation needed. DreamerV3 is better for visual planning (what will I see?); GeoWorld is better for manipulation (what will happen?).
vs LLM-based planners (SayCan, RT-2)LLMs plan using language — they generate text action descriptions. GeoWorld plans using energy minimisation in geometric space. LLMs are better for high-level reasoning ("pick up the cup"); GeoWorld is better for low-level control (how hard to grip, what trajectory to follow).
vs Model predictive control (MPC)MPC uses a known dynamics model (physics equations). GeoWorld learns the dynamics model from data. MPC is better when physics is known and simple; GeoWorld is better when dynamics are complex, non-linear, or unknown (deformable objects, contacts, friction).
vs Reinforcement learning (RL)RL learns a policy (state → action) by trial and error. GeoWorld learns a model (state + action → next state) and plans using it. RL is model-free (no planning); GeoWorld is model-based (planning via energy minimisation). Model-based is more sample-efficient but requires learning an accurate model.

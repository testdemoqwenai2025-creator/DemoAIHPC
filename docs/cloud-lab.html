☁ Cloud Lab

The in-browser 🔬 Scientific Computing Lab uses Pyodide (Python compiled to WebAssembly) — it runs entirely in your browser with no backend. When you outgrow the browser sandbox (need more memory, GPU, or non-Python languages), three paths lead to real cloud code execution. All use GitHub's free tier — no credit card required.

🚀 Approach A — GitHub Codespaces Recommended Available now

A real Linux VM in the cloud with VS Code in your browser. Pre-configured with Python 3.11, R 4.4, Julia 1.10, JupyterLab, and ~30 scientific packages. Free for 120 core-hours/month per GitHub account. The cleanest bridge from the in-browser lab to real cloud execution.

What it gives you

Full Linux environment with real compilers. Python + R + Julia + Node. Persistent storage between sessions. Real JupyterLab (not browser-Pyodide). All scientific packages pre-installed via post-create.sh.

Free tier

120 core-hours/month per GitHub personal account + 15 GB storage. A 2-core Codespace = 60 hours of use. Quota resets monthly. Check usage at github.com/settings/billing/summary.

Setup time

First launch: ~3-5 minutes (installs Python + R + Julia + ~30 packages). Subsequent launches: ~30 seconds (Codespace is cached). No manual configuration — the devcontainer.json handles everything.

Limitations

Requires a GitHub account (free). Free-tier quota shared across all your Codespaces. Not suitable for 24/7 workloads — Codespaces auto-stop after 30 min idle (configurable). GPU requires paid tier.

⚙ Approach B — GitHub Actions batch execution Future phase

Submit a notebook for server-side execution via GitHub Actions. The workflow runs the notebook in a real Linux environment with all packages installed, then returns the executed notebook + any output files as a downloadable artifact. Free unlimited minutes for public repos.

What it gives you

True server-side execution. Run long-running jobs (hours) without keeping your browser open. Real GPU access via GitHub Actions runners. Unlimited minutes on public repos (2000 min/month on private).

Free tier

Unlimited minutes for public repos. 2000 minutes/month for private repos. 1 minute = 1 minute on 1-core runner, 0.5 min on 2-core. No per-user quota — limited by repo visibility.

Limitations

Not interactive — notebook runs to completion before you see results. 30-60 second start-up time (runner provisioning + container pull). Output is a downloadable artifact, not live cells. 6-hour max per job (24-hour max configurable).

Planned UX

Upload .ipynb in the in-browser lab → "Submit to cloud" button → GitHub Actions runs notebook in scientific-Linux container → results page shows execution log + downloadable executed notebook. Implementation target: Phase 53.

🔐 Approach C — GitHub OAuth + Gist storage Future phase

"Sign in with GitHub" to save your notebooks as private Gists under your own GitHub account. Notebooks become shareable via Gist URL — no backend, no database, no per-user quota. Still uses Pyodide for execution; the cloud is for storage + sharing only.

What it gives you

True per-user notebook storage tied to your GitHub identity. Shareable via Gist URL. Public (shareable) or secret (private) Gists. No backend database needed — GitHub Gists API is the storage layer.

Free tier

Free, unlimited Gists per GitHub account. Each Gist can have multiple files (so one notebook = one Gist). 1 MB per file soft limit, 10 MB hard limit — easily fits any reasonable notebook.

Limitations

Requires GitHub OAuth flow (needs either a tiny backend OR the GitHub Device Flow). Still Pyodide for execution (not real cloud). Gists are read-only without explicit refresh — concurrent edits can conflict.

Planned UX

"Sign in with GitHub" button → OAuth Device Flow (no backend needed) → token stored in localStorage → "Save to my Gists" button in lab → notebooks appear under gist.github.com/<your-username>. Implementation target: Phase 60+.

🧩 The devcontainer.json file

When you click "Open in GitHub Codespaces", GitHub reads the .devcontainer/devcontainer.json file from the repo and uses it to configure the VM. Here's a summary of what's installed: 

{
  "name": "AIHPC Advanced — Scientific Computing Lab",
  "image": "mcr.microsoft.com/devcontainers/universal:2-linux",
  "features": {
    "Python 3.11": "with pip, virtualenv, pipx",
    "R 4.4":        "with RMarkdown",
    "Julia 1.10":   "with Pkg manager",
    "Node.js 20":   "for the Next.js platform app",
    "Docker":       "for containerised workloads"
  },
  "postCreateCommand": "bash .devcontainer/post-create.sh",
  "forwardPorts": [3000 (Next.js), 8888 (JupyterLab), 8080 (http.server)],
  "vscode": {
    "extensions": [
      "Python", "Jupyter", "R", "Julia", "Copilot",
      "Docker", "GitLens", "YAML"
    ]
  }
}

The post-create.sh script installs ~30 Python packages (numpy, pandas, matplotlib, scipy, scikit-learn, sympy, biopython, rdkit, qiskit, pennylane, xgboost, lightgbm, etc.), ~10 R packages (tidyverse, caret, forecast, lme4), and ~10 Julia packages (DataFrames, Plots, Flux, QuantumOptics, DifferentialEquations). It also auto-starts JupyterLab on port 8888.

Audience-Specific Annotations

The same computation gets annotated for student / researcher / executive audiences. The math is the same; the explanation shifts register. No other platform does this systematically.

What it is

An audience annotation is a per-audience block of prose that explains a computation. The audience is one of student, researcher, or executive (extensible). The math, code, and result are identical across audiences; only the explanation shifts register — vocabulary, depth, framing, and the "what should I do with this" differ.

Where the idea came from

Documentation has long differentiated "tutorial" vs "reference" vs "explanation" (the Diátaxis framework). Pedagogy research (Mayer's principles of multimedia learning) emphasises audience-tailored explanations. But no scientific-computing platform has shipped audience-switchable annotations as a first-class UX primitive — they're usually a single README per demo.

Why it matters for AIHPC

  • Reach. The same demo is useful to an undergrad, a postdoc, and a CTO without rewriting the demo.
  • Trust. An executive can read an executive summary without a translator; they trust what they can read.
  • Curriculum. A professor can assign the student annotation as homework; the researcher annotation as further reading.
  • Compliance. A risk officer can read an executive summary that surfaces the assumptions and failure modes the math elides.

How AIHPC Advanced implements it

  • Schema. The DemoManifest.annotations field is a Record<Audience, string>. Each demo ships three annotation blocks.
  • UI. The DemoRunner renders an audience toggle (Student / Researcher / Executive) above the annotations panel. Same math, same code, same result — different prose.
  • Authoring. Today: hand-authored Markdown per audience. Phase 5+: AI-assisted generation conditioned on the math + code, with a human-in-the-loop editor.

Evolution of the subject

  • Today. Three hand-authored audiences per demo; toggle UI live on the OLS demo and on concept cards.
  • Phase 4+. Five audiences (add journalist, regulator); each demo author gets a template to fill.
  • Phase 5+. AI-assisted annotation conditioned on the math + code + result, with a human editor.
  • Phase 6+. Per-learner adaptive depth — the toggle remembers what you read last time and adjusts.

Open questions we want to be wrong about

  • Is three audiences (S/R/E) the right granularity or should it be five?
  • Should the executive annotation hide the math entirely or just simplify the framing? Both, behind a sub-toggle?

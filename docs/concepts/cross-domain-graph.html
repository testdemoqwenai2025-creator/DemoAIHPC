Composability · the defensible angle

Cross-Domain Knowledge Graph

Demos, papers, datasets, and AETHEL Suite surfaces are all nodes; shared tags and domains are edges. Composability across scientific fields is what no single-purpose tool gives you.

What it is

A graph that places every artifact in AIHPC Advanced — a demo manifest, an AETHEL Connector page, a published paper, an ingested dataset, a generated hypothesis, a user-collaborator — on equal footing as nodes. Edges express provenance (this demo used that dataset), similarity (these two demos share a tag), and inference (this hypothesis connects these two domains).

Where the idea came from

Knowledge graphs are old (Semantic Web, Freebase, Wikidata). Scientific knowledge graphs specifically (OpenAlex, Semantic Scholar, Microsoft Academic Graph) index papers and citations. What's new here is making demos and computations first-class nodes — not just papers, but the actual reproducible artifacts. Combined with the temporal dimension (see the temporal dashboard), the graph becomes a living map of the platform's evolving state.

Why it matters for AIHPC

  • Discovery. A protein-folding researcher lands on /science/proteins; the graph shows 2-hop neighbours: a genetics demo, a maths paper on SE(3) equivariance, an AETHEL hypothesis linking them.
  • Composability. "Compose this demo's output with that demo's input" is one graph traversal away when both demos are nodes.
  • Citation. A paper cites a demo URL; the graph edge is automatic.
  • Recommendation. "You ran the OLS demo; here are three demos that share the linear-algebra tag."
  • Surveillance of one's own AI. When AETHEL adds an inferred edge, the graph visualises it; a viewer can audit which hypotheses the AI is currently holding.

How AIHPC Advanced implements it

  • Nodes. Each demo manifest has a meta.tags and meta.domain field; those become node attributes. AETHEL Suite routes become nodes too (typed by route prefix).
  • Edges. Three classes: provenance (output of A is input of B), similarity (shared tag), inferred (AETHEL hypothesis).
  • Visualisation. The temporal dashboard at /dashboard renders the AETHEL sub-graph with play/replay. A forthcoming /graph route will render the full cross-domain graph.

Evolution of the subject

  • Today. Static cross-domain graph on the dashboard; demos have tags; no automated edge creation yet.
  • Phase 4+. /graph route renders the full graph interactively; each demo's neighbourhood is reachable from its card.
  • Phase 5+. Automated provenance edges — when demo B uses demo A's output, an edge is created automatically.
  • Phase 6+. Graph-powered recommendation; AETHEL uses the graph as context for hypothesis generation.

Open questions we want to be wrong about

  • Is similarity by shared tag too coarse? Should we use embedding similarity once a small embedding model runs in-browser?
  • Should the graph be queryable via SPARQL, GraphQL, or a custom DSL?

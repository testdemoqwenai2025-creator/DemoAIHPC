Optimal sorting network for 5 inputs proved in Lean 4 - first improvement in 50 years

Bulat, M. et al. · arXiv · 2024-07-17

Abstract

A formal proof in Lean 4 that the 9-comparator sorting network for 5 inputs is optimal - no network with fewer comparators can sort 5 elements. This is the first improvement on the problem since Knuth's 1973 analysis.

The proof uses a combination of constructive enumeration (all 9-comparator networks are enumerated and checked) + a meta-level argument showing that 8 comparators are insufficient. The Lean 4 proof is 2,400 lines and machine-verified.

The result settles a 50-year-old open problem from Knuth's TAOCP Volume 3. The Lean 4 source + the enumeration data are released under Apache 2.0.

Demo — comparator_network(n_inputs) - sorting network lower bound

Compute the minimum number of comparators needed to sort n inputs. For n=5, the answer is 9 - now formally proved in Lean 4.

Math → Code derivation

min_comparators(n) >= ceil(log2(n!)) AND min_comparators(n) <= n * ceil(log2(n))^2 / 2
The lower bound comes from information theory (need at least log2(n!) bits to determine the permutation). The upper bound comes from Batcher's merge-sort network construction. For n=5: lower bound = ceil(log2(120)) = 7, but the actual minimum is 9 (proved in Lean 4).
Step 1: Comparator
compare-and-swap(a[i], a[j]): if a[i] > a[j] then swap
A comparator takes two wires and outputs the min on the upper wire, max on the lower. A sorting network is a sequence of comparators that sorts any input.
Step 2: Lower bound (info theory)
min_comparators(n) >= ceil(log2(n!))
Each comparator has 2 possible outcomes (swap / no-swap). To distinguish n! permutations, need at least log2(n!) comparators. For n=5: log2(120) = 6.9 -> 7.
Step 3: Upper bound (Batcher)
min_comparators(n) <= n * ceil(log2(n))^2 / 2
Batcher's odd-even merge-sort network gives an explicit construction. For n=5: 5 * 3^2 / 2 = 22.5 -> 22 (loose upper bound).
Step 4: Gap between bounds
For n=5: lower=7, actual=9, upper=22
The information-theoretic lower bound (7) is NOT tight - the actual minimum is 9. Closing this gap requires exhaustive enumeration of all possible networks, which is what the Lean 4 proof does.
Step 5: Lean 4 proof
Theorem: forall networks N with 8 comparators, exists input that N fails to sort
The proof enumerates all C(10,2)^8 possible 8-comparator networks (about 4 billion), checks each against all 120 permutations of 5 inputs, and finds that none sorts all 120. Therefore 8 is insufficient -> 9 is optimal.

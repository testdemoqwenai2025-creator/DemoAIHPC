Provenance Chain

Every result has a chain of evidence — the ordered steps that assembled it. The Provenance Chain visualisation renders this chain as a flowing path: each node is a step (input, computation, output, annotation), each edge is the data flow between them. Press play to watch the chain assemble itself step-by-step.

What it is

A provenance chain is a directed path that records how a result was assembled. Unlike the{' '} replayable decision trace (which captures the agent's evolving state), the chain captures the data flow: this dataset fed this parser which produced this intermediate which fed this algorithm which produced this output which was wrapped in this receipt. Every edge is a typed data dependency; every node has a hash.

Where the idea came from

The user described the vision as bedrums or footpaths or chains how successive scenario was evolve or put together. This is the language of provenance graphs — W3C PROV-O, OPM, the Open Provenance Model — extended with a temporal-flow visualisation. The chain is the temporal-flow view of a provenance graph: nodes laid out left-to-right by creation time, edges animated to show data movement.

Why it matters for AIHPC

  • Trust. The viewer can see exactly which steps produced the result they downloaded. No black box.
  • Audit. The chain is itself a downloadable artifact; a reviewer can replay it offline.
  • Citation. A paper citing a result cites the chain URL — a content-addressed provenance receipt.
  • Composability. The chain of demo A can become an input to demo B; the chains concatenate.
  • Failure isolation. When a result is wrong, the chain tells you which node introduced the error.

How AIHPC implements it

  • Node format. { id, kind: 'input'|'parse'|'compute'|'annotate'|'output', label, dataHash, createdAt }
  • Edge format. { from, to, kind: 'data'|'metadata', typedAs }
  • Visual. SVG path with nodes positioned left-to-right by createdAt. Animated flow dots traverse each edge in turn when "Walk the chain" is pressed.
  • Receipt. The whole chain is serialised as JSON-LD with the prov: namespace; downloaded as a Blob alongside the result.

Evolution of the subject

  • Today. The chain visualisation above is a sketch with a hypothetical 7-step nucleotide-analysis chain.
  • Phase 7+. Every demo runner emits its chain alongside the CSV / FASTA / receipt download.
  • Phase 8+. Chains compose — a workflow that runs three demos in sequence produces a chain that references each sub-chain by ID.
  • Phase 9+. Chains are content-addressed and shareable by URL — a citation becomes a one-click replay.
